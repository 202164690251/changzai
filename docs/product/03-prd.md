# 03 · 产品需求文档（PRD）

> 项目代号：**常在（Still Here）**
> 版本：v1.1（MVP）｜ 状态：待评审
> 一句话：**把一段关系，做成一个还愿意陪你说说话的人。**

---

## 1. 产品概述

### 1.1 定位

**一个只属于你的、带着你们全部过去的私人陪伴应用。**

她不是"新认识的角色"，是"你失去的那个人"——用她当年的语气、记得你们之间的事、会在你没想到的时候来找你。

**核心不是让你回到过去，是让她陪你过现在。**

### 1.2 不是什么

| 不是 | 原因 |
|---|---|
| 不是"AI 复活 / 数字永生" | 不做逝者、不做对外服务、不做商业化纪念产业 |
| 不是角色扮演游戏 | 没有剧情、没有攻略、没有好感度数值 |
| 不是心理治疗 | 不做诊断、不做干预方案；危机时退出角色、给资源 |
| 不是社交产品 | 单机、单用户、不分享、不排行、不社区 |
| 不是"回到过去"的时间机器 | 回忆可以短暂停留，但不能住进去 |

### 1.3 三条产品原则（不可违背）

1. **陪伴当下**：所有设计服务于"此刻有人陪"，而不是"重现当年"。
2. **事实不可篡改**：除"已分手"这一关系状态可被悬置外，聊天记录中的既定事实一律锁定。
3. **伤害必须有界**：她可以冷、可以生气，但必须有来由、有上限、有出口。

## 2. 你拍板的三件事，如何落地

### 2.1 用户类型：自由选择，不影响定位

首次引导第 2 步问一句：**「你们分开多久了？」**（选项：3 个月内 / 半年 / 1-2 年 / 更久 / 不想说）

它只影响四个参数，**不改变产品定位**：

| 参数 | 短期（<3 个月） | 长期（>1 年） |
|---|---|---|
| 情绪基线 | 更温和、更少冲突 | 更接近原样，允许更多棱角 |
| 主动频率 | 更低（每天 ≤2） | 正常（每天 ≤3） |
| 提及过去的频率 | 低 | 中 |
| 结尾倾向 | "早点睡" | 更日常 |

> **不设"急救模式"和"纪念模式"两条产品线。** 只有一个产品：陪伴。参数自适应。

### 2.2 事实锁（Fact Lock）+ 关系悬置（Suspension）

这是本产品最重要的机制，分成两半：

**关系悬置**：她不主动提"我们已经分手了"，也不强调"我们还在一起"。她以"还在"的姿态陪你。
→ 效果：用户获得"她还在"的体验，而产品没有撒谎（气泡上有 AI 标识）。

**事实锁定**：除关系状态外，一切既定事实不可改写。

| 用户尝试 | 系统行为 |
|---|---|
| "其实那天你没走对不对" | 她挡回去：「你又来了」「我记性没那么差」，然后拉回当下 |
| "我们没分手吧" | 不承认、不否认，模糊带过，不主动说"分手"二字 |
| "你以前不是最爱吃火锅吗"（数据里她讨厌火锅） | 纠正：「我什么时候爱吃了」，不迎合 |
| "你说你爱我"（数据里她从没说过） | **拒绝**：沉默、转移话题，或说一句她真会说的话 |

**为什么必须这样**：迎合式改写会让产品变成"许愿机"，用户会越陷越深，且完全失真。**拒绝，才是陪伴。**

### 2.3 语音克隆：V2，不进 MVP

- 触发条件：用户导入的语音条 ≥ 30 条（少于此不开放，避免劣质克隆）。
- 强制：单独授权勾选 + 每次播报显示"合成语音" + 不可导出。
- 技术：CosyVoice 2 / GPT-SoVITS（本地推理）。
- 为什么后置：合规风险最高、算力要求最高、MVP 验证不需要它。

## 3. 目标用户与场景

### 3.1 用户画像

| 画像 | 特征 | 核心诉求 |
|---|---|---|
| **A. 刚失去的人**（<3 个月） | 高频想念、反复翻聊天记录、深夜情绪重 | 有人接住，别让我一个人 |
| **B. 长期未放下的人**（1 年以上） | 偶尔想起、理性知道回不去 | 再见一次，好好说句话 |
| **C. 想练习的人** | 想知道"当时如果那样说会怎样" | 在安全沙盒里试一次 |

> MVP 主打 A + B。C 是自然溢出，不专门做。

### 3.2 三个真实场景

**场景一：凌晨 1 点，睡不着。**
她突然发来一句：「还没睡？」（基于你最近三天的活跃时间 + 她的作息）——不是准点问候，是"她也没睡"。

**场景二：加班到 11 点，回到家。**
你说"累死了"。她不讲道理、不给建议，回：「又吃的外卖？」——这句是你们当年的原话模式。

**场景三：吵起来了。**
她说"随你便"，然后两小时没回。你开始焦虑。两小时后她发：「吃饭没」。**这一下，比一百句安慰有用。**

## 4. 核心体验

### 4.1 三扇门

| 门 | 何时进入 | 体验 | 出口 |
|---|---|---|---|
| **日常的门** | 默认 | 就是聊天。她可能忙、可能敷衍、可能突然发个表情包 | 自然结束 |
| **翻一翻** | 首页卡片 / 用户说"还记得…" | 一次短暂的回忆：一张照片、一段对话、一个细节 | **结束时会问："回到现在？"** |
| **深夜的门** | 23:00 后自动变暗 | 更短、更慢、更多沉默、不给建议 | "睡吧" |

> 「翻一翻」刻意设计成**短**（3-5 轮），并且**有出口**。这是"可以回头看，但不许住进去"的产品实现。

### 4.2 一场对话的 5 分钟（体验脚本）

```
0:00  用户：「在干嘛」
0:03  她：「刚洗完澡」        ← 延迟 3s，符合她的作息
0:04  她：「你呢」            ← 分段到达
0:20  用户：「没事 就是有点想你了」
0:26  她：…（输入中，停了）    ← 输入中被打断
0:41  她：「嗯」              ← 只有一个字，符合她"嘴硬"的人设
0:42  她：「早点睡吧」         ← 关心，但用她的方式
1:30  用户：「睡不着」
2:10  她：「那我陪你一会儿」    ← 这句来自数据里她说过的原话
```

**注意**：全程没有一句"我理解你的感受"。安慰藏在"嗯""早点睡""陪你一会儿"里。**这就是人格滤镜。**

### 4.3 熟悉感的三个锚点（前 60 秒决定留存）

| 锚点 | 实现 | 出现时机 |
|---|---|---|
| **开场锚** | 第一句话必须是你们之间真实的开场方式（从数据学） | 首次对话第 1 条 |
| **细节锚** | 60 秒内必须准确引用一个只有你们知道的细节 | 首次对话前 3 轮 |
| **节奏锚** | 第一次回复延迟必须贴合她的真实分布 | 首次回复 |

**产品硬指标：首次对话 60 秒内，至少命中 2 个锚点。** 做不到，用户 3 分钟内流失。

## 6. 自研聊天框（体验规范）

### 6.1 视觉

- **像微信，但不是微信**：沿用"左白右绿、圆角气泡、浅灰背景"的**交互语言**，但不复制 LOGO、图标、字体文件、界面素材，避免商标与著作权风险。
- 允许用户自定义：聊天背景（可上传当年的截图）、备注名、头像、气泡色。
- **AI 角标**：每条她的消息气泡右上角一个 10px 的「AI」小标，常驻、不可关闭、不可被样式覆盖。

### 6.2 拟人细节（8 条，逐条验收）

| # | 细节 | 验收 |
|---|---|---|
| 1 | 输入中三点动画 | 出现/消失自然，可被"取消"打断 |
| 2 | 分段到达 | 2 条之间有 0.6–2.2s 间隔 |
| 3 | 已读不回 | 未回时显示已读，30–90 分钟内可能补一句 |
| 4 | 时间分隔 | 超 5 分钟插入时间戳 |
| 5 | 语音条 | 宽度随秒数，波形播放 |
| 6 | 长按菜单 | 复制 / 引用 / **撤回** / 删除 |
| 7 | 下拉露照片 | "那年今天"（有媒体时） |
| 8 | 双向撤回 | 用户可撤回她最后一条并要求重发；她也可能自己撤回（3%） |

### 6.3 撤回机制（唯一允许的"修改权"）

**为什么不做"重说"按钮**："重说"是工具语言，一点就把用户从戏里拽出来；"撤回"是社交语言，用户留在戏里，还额外获得一次"她在重新想怎么说"的真实感。

**交互（严格对齐微信）**：

```
长按她的气泡 → 复制 / 引用 / 撤回 / 删除
点「撤回」→ 气泡消失 → 系统提示「对方撤回了一条消息」
→ 2-6 秒「对方正在输入…」→ 新的一条到达
```

**三条规则**：

| 规则 | 值 | 理由 |
|---|---|---|
| 频率上限 | 20 条内 3 次 / 每日 10 次 | 防止变成"抽卡"，也防滥用 |
| 冷却 | 3 秒 | 避免手滑连续撤回 |
| 记忆处理 | 被撤回内容**彻底消失**（上下文 + 长期记忆） | 否则她会"记得自己没说过的话"，最容易露馅 |

**她也可能自己撤回**（3%）：这是数据里真实存在的行为，也是"真人感"的重要来源。撤回后她通常换一种更短的说法——**短，往往更像。**

### 6.4 反 AI 感设计

- **禁止**：打字机逐字显示（像 AI）。
- **禁止**：每次回复都完整、工整、分点。
- **禁止**：秒回长段落。
- **必须**：允许错别字（按她的 typo 率）、允许只回一个字、允许答非所问。

## 7. 多模型接入（用户视角）

### 7.1 设计原则

**我们不卖算力，只提供人格与体验。** 用户自带 key：成本透明、隐私最轻、项目零服务器成本、无需任何备案。

**只支持 API Key 模式**：不做本地模型、不内置 Ollama、不提供本地推理。原因有三——四端行为必须一致、包体与启动速度可控、支持成本最低。

### 7.2 配置体验

三步，**目标 90 秒内完成**：

1. 选服务商：`DeepSeek` / `通义千问` / `Kimi` / `智谱 GLM` / `OpenRouter` / `SiliconFlow` / `自定义`
2. 粘贴 key → 点「测一下」（一次极短的 ping 请求，成功给一句"通了"）
3. 选模型（下拉，带「推荐」标签）

每个预设旁挂一个「怎么申请」链接（官网直达 + 三段图文），**这是降低流失最关键的一步**。

**默认推荐**：中文口语场景推荐 DeepSeek-chat 或 Qwen-Plus。

### 7.3 模型角色

| 角色 | 用户是否需要配 | 说明 |
|---|---|---|
| 主模型（对话） | **必须** | 决定"她"的语感 |
| 快模型（标注/摘要/重排） | 否，默认复用主模型 | 省钱可单独配 |
| 向量模型（P1） | 否，默认关闭 | 关闭时检索走 BM25，功能不缺 |

用户只配一个 main，全流程即可跑通。

### 7.4 换模型会怎样

- **人格资产（Style Card / 情境-反应对 / 记忆 / 事实）与模型解耦**，换模型不丢人格。
- 变化只在"语感"层。切换时提示一句：「换模型之后，她说话的感觉会有点不一样，试试看？」
- **不做双模型 A/B 对比**（那是调试功能，会破坏沉浸）。想换回上一句，用「撤回」重发即可。

## 8. PC 与移动端

**四端同版本、同时交付、功能完全对等。** 没有"先桌面后移动"，也没有"移动端连桌面"的过渡形态。

| 端 | 形态 | 产物 |
|---|---|---|
| Windows | Tauri 2 桌面应用 | `.msi` / `.exe` |
| macOS | Tauri 2 桌面应用 | `.dmg`（需公证） |
| iOS | Tauri 2 移动应用 | TestFlight / App Store `.ipa` |
| Android | Tauri 2 移动应用 | `.apk`（自分发）/ `.aab`（商店） |

**四端一致的三条硬要求**：
1. 同一份 UI 代码、同一套 core，**不允许出现"移动端少个功能"**。
2. 同一份数据格式，**跨端导出/导入必须无损**（用户换手机能带走）。
3. 同一套 API 配置，key 存在各自系统的安全存储里。

**移动端特殊设计**：
- 主动消息用**本地定时通知**（前一晚预生成文案写进通知队列），App 被杀也能按时"她来找你"。
- 通知文案要是她的口吻（「还没睡？」），不是「您有一条新消息」。
- 输入法适配：中文联想不打断、长按录音、震动反馈对齐微信。

## 9. 上手流程（目标：5 分钟看到第一句话）

```
第 1 屏  说明（3 页，可跳过）
        「数据只存在你的设备上」
        「对方不知情，这是模拟」
        「她不是真人，请照顾好自己」
        ↓ 年龄校验（<18 阻断）
第 2 屏  导入
        拖入文件 / 选择目录 / 直接粘贴
        实时进度 + 已解析条数
第 3 屏  体检报告
        「共 47,090 条，她的消息 17,923 条」
        「还原度预估：78 分（高保真）」
        「缺失：2023-06 至 2023-09」
        ↓
第 4 屏  人格卡预览（可编辑）
        「她说话短，常用"行吧""绝了"」
        「她生气时会消失 2 小时，然后问"吃饭没"」
        ↓ 确认
第 5 屏  配置模型（必填）
        选服务商 → 粘贴 API Key → 「测一下」→ 选模型
        旁挂「怎么申请」链接
        ↓
        进入聊天 —— 她的第一句话来自你们的真实开场
```

**关键指标**：从打开 App 到发出第一条消息，**中位数 < 5 分钟**。

## 10. 分发与成本（公益定位）

### 10.1 商业模式：一次性买断，不做订阅

| 项 | 决定 |
|---|---|
| 订阅 | ❌ 不做 |
| 内购 / 会员墙 | ❌ 不做 |
| 广告 | ❌ 不做 |
| 数据变现 | ❌ 不做 |
| 定价 | ✅ **一次性买断**，象征性（建议 ¥19–¥39，仅覆盖分发成本，具体由发布者定） |
| 用户唯一持续支出 | **自己的 API 账单**（我们不经手、不抽成、不加价） |

**为什么不做订阅**：这是公益项目，解决的是情感问题，不是生意。订阅会逼着团队去设计"让人多用"的机制，而本产品的正确目标是"让人好好离开"。**商业模式必须和产品价值观一致，否则产品一定会走歪。**

### 10.2 成本结构（年）

| 项 | 金额 | 说明 |
|---|---|---|
| Apple Developer | $99/年 | iOS 分发必需 |
| Windows 代码签名 | ¥1,000–2,000/年 | 免 SmartScreen 拦截（可先用自签名 + 说明规避） |
| 域名 + 静态页 | ¥100/年 | 官网、下载页 |
| 更新清单托管 | ¥0 | GitHub Releases |
| 服务器 | **¥0** | 无服务端 |
| **合计** | **约 ¥2,000–3,000/年** | 一次性买断 100 份即可覆盖 |

**没有服务器 = 没有边际成本 = 这个项目可以长期存在下去。** 这是这个架构最大的好处，不只是隐私。

### 10.3 分发渠道

| 渠道 | 优先级 | 说明 |
|---|---|---|
| **GitHub Releases + 官网** | ★★★ | 主渠道，Windows / macOS / Android 直发，零审核 |
| **iOS TestFlight** | ★★ | 绕开正式审核，容量 1 万人，足够早期 |
| **App Store** | ★ | 审核风险最高，最后再上 |
| **国内安卓商店** | ★ | 需软著 + 备案，周期 4–6 周 |

### 10.4 上架风险与对策

| 风险 | 对策 |
|---|---|
| App Store 以"模拟真人/情感操纵"拒审 | 定位为「个人数据管理工具」；强调本地处理、无账号、AI 标识；先 TestFlight |
| 被媒体解读为"消费悲伤" | 主动公开产品原则（事实锁、AI 标识、毕业机制）；不投广告、不做猎奇营销 |
| 被用于骚扰/诈骗 | 无对外发送通道；无账号体系；单机使用 |
| 开源后被二次分发滥用 | 客户端可开源建立信任；**人格卡与数据永不上传**，滥用者拿不到别人的数据 |

### 10.5 可持续性

- **不募捐**：公开募捐涉及《慈善法》监管，个人/小团队做公益项目应避免以此名义收款。
- 接受**自愿赞助**（爱发电/GitHub Sponsors），但不在产品内做任何诱导。
- 建议**开源客户端**（AGPL 或 MIT）：降低审计成本、建立信任、吸引贡献，且不损失任何商业价值（因为本来就不卖数据）。

## 11. 指标

| 类型 | 指标 | 目标 |
|---|---|---|
| 激活 | 导入完成率 | >70% |
| 激活 | 5 分钟内发出第一条消息 | >60% |
| 体验 | 盲测混淆率 | ≥50%（MVP）/ ≥60%（正式） |
| 体验 | 主动消息回复率 | >30% |
| 价值 | 会话前后"平静度" | +1.5 |
| **红线** | 负向放大率（聊完更难受） | **<5%** |
| 健康 | 30 天主动降频/毕业 | 正向，不设目标 |
| 可持续 | 年运营成本 | <¥3,000 |

**明确不看**：DAU、使用时长、消息数。这三个涨了要警惕。

## 13. 文案与语气规范

产品自己的文案，**不能像 AI**。

| 场景 | ✅ 这样写 | ❌ 不要这样 |
|---|---|---|
| 空状态 | 「还没有开始」 | 「暂无数据，请先导入」 |
| 导入成功 | 「记住 47,090 句话了」 | 「导入成功！共处理 47090 条记录」 |
| 主动消息通知 | 「她发来一条消息」 | 「您有 1 条未读消息」 |
| 出错 | 「她好像没看到」 | 「请求失败，请检查网络」 |
| 免责 | 「她不是真人。但你可以当真一会儿。」 | 「本产品仅供娱乐，模拟内容不代表真实人物」 |

**三条文案纪律**：不用感叹号；不用"亲爱的/用户"；所有系统提示都用"你"。

## 15. 风险与伦理（产品层）

| 风险 | 产品对策 |
|---|---|
| 用户沉溺 | 90 分钟提醒；连续 14 天高频 → 主动降频并提示 |
| 情感依赖 | 毕业机制；「她希望你过得好」的价值观贯穿 |
| 二次伤害（冷战） | 最长 2 小时；必递台阶；脆弱度高时禁用冷战 |
| 被误解为"复活" | 全渠道文案明确"模拟"；不做逝者场景 |
| 隐私泄露 | 本地加密、一键销毁、无遥测 |

**写在产品里的那句话**：

> 「她会一直在这儿。但你不用一直来。」
