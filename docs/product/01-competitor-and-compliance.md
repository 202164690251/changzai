# 01 · 竞品分析与合规风险

> 项目代号：**常在（Still Here）**
> 版本：v1.1 ｜ 用途：立项评审 / 投资沟通 / 团队对齐
> 说明：本文法律部分为产品风险梳理，不构成法律意见，正式上线前须由执业律师出具合规意见。

---

## 1. 结论摘要

1. **市场存在真实空位**：现有产品要么强在"角色扮演"（弱在关系连续性），要么强在"陪伴聊天"（弱在记忆细节），要么强在"工具链"（弱在情绪设计）。**「关系连续性 + 情绪弧线 + 本地私密 + 用户自带模型」四者交集目前无人占据。**
2. **开源侧没有可直接商用的竞品**：人格蒸馏 Skill 全是 Prompt 工程产物，无运行时、无记忆、无主动性、无 UI，且普遍停更。它们是"素材"，不是"产品"。
3. **商业侧没有做「已分手关系」的**：Character.AI / 星野 / 猫箱等做的是"新角色"，不是"旧的人"。**这是本产品最大的差异化，也是最大的合规敏感点。**
4. **合规风险可控，但取决于三个设计选择**：本地优先、单用户、显式 AI 标识。一旦改成云端多用户或开放分享，合规成本指数上升。
5. **最大风险不是法律，是伦理与心理**：产品天然带有"强化反刍思维"的倾向，必须有内置降温与退出机制，否则口碑与监管都会反噬。

## 4. 逐类分析

### 4.1 开源人格蒸馏 Skill（L1）

**共同范式**：`聊天记录 → LLM 总结 → 一份 Markdown 人格卡 → 塞进 system prompt`。

- **优点**：门槛极低、隐私友好、情绪共鸣强（这也是 star 高的原因）。
- **死穴**：① 静态蒸馏丢失长尾；② 无跨会话记忆；③ 无主动性；④ 无部署能力；⑤ 不可度量。
- **对我们的意义**：**它们是"人格卡模板"的免费参考，不是竞品。** 我们应当吸收其 `Part A 记忆 / Part B 人格` 的分层思路和 `Correction 层`，但把产物从"散文"改成"可执行资产"。

**关键教训（来自 ex-skill issue 区）**：
- 「1 万 8 千条记录，我一眼就看出来不是她」→ 纯蒸馏路线有天花板。
- 「每次启动都重新开始，不记得上次聊了啥」→ 记忆是刚需，不是加分项。
- 「下午被 Claude 伦理锁了」→ 模型拒答是真实的产品故障，必须有多模型兜底。

### 4.2 商业 AI 陪伴（L2）

- **Character.AI**：赢在角色供给与社区，输在"关系"——每个角色都是新认识的，没有共同历史。
- **Replika**：最接近"陪伴"，情绪与主动性做得最好；但角色是"为你而生的人"，不是"你失去的人"。且近年因安全策略收紧，情感深度被削弱。
- **国内产品（星野/猫箱/筑梦岛）**：赢在内容供给与移动端体验，输在审核约束与"私人性"——它们本质是内容平台，不是私人纪念品。
- **共同空白**：**没有一家做"带着真实历史而来的那个人"**。这既是机会，也是它们不敢碰的原因（合规与伦理）。

### 4.3 数字永生/纪念（L3）

- 模式重（访谈、剪辑、托管），价格高，面向逝者。
- **启示**：这类产品卖的不是"聊天"，是"仪式感"与"被保存"。我们的"毕业信 / 纪念册"应当借鉴其仪式设计。

### 4.4 接入与运行时（L4）

- AstrBot / LangBot / NapCat / SillyTavern 是**能力供给方**，不是竞品。
- **我们的策略**：核心运行时自研，接入层做成适配器（未来可对接 QQ/微信），**不把产品绑死在任何一个框架的生命周期上**。

## 5. 市场空位与我们的位置

**空位定义**：`关系连续性 × 情绪弧线 × 本地私密 × 自带模型`

| 维度 | 现有产品 | 我们 |
|---|---|---|
| 人格来源 | 新造 / 平台供给 | **真实聊天记录** |
| 关系 | 从零开始 | **带着历史来** |
| 情绪 | 单轮情绪 | **多轮弧线 + 冷战 + 和解** |
| 记忆 | 摘要 / 向量 | **四层 + 情绪一致检索 + 有分寸的遗忘** |
| 主动性 | 推送式 | **欲望×机会，有来由** |
| 数据 | 云端 | **本地优先，可一键销毁** |
| 模型 | 封闭 | **用户自带 key，任意模型** |
| 结局 | 无限陪伴 | **有毕业机制** |

**一句话定位**：*别人的产品是"认识一个新的人"，我们的是"再见一次那个人，然后好好回到现在"。*

## 6. 法律法规风险

### 6.1 中国法（核心）

| 法规 | 关键条款 | 对本产品的要求 | 风险等级 |
|---|---|---|---|
| **《个人信息保护法》** | 第 13 条（合法性基础）、第 23 条（向第三方提供须单独同意）、第 28 条（敏感个人信息）、第 47 条（删除权）、第 51 条（安全措施）、第 55 条（事前 PIA） | 聊天记录是**双方**的个人信息；本地处理+仅自己使用，风险最低；一旦上传云端或用于训练共享模型，需取得对方同意（事实上不可能） | 🔴 高 |
| **《民法典》人格权编** | 第 1019 条（不得利用信息技术手段伪造他人肖像）、第 1023 条（**声音参照肖像权保护**）、第 1024 条（名誉）、第 1032 条（隐私）、第 994 条（死者人格利益） | **语音克隆（V2）是明确的高风险点**；生成内容若贬损对方可能构成名誉侵权 | 🔴 高 |
| **《互联网信息服务深度合成管理规定》** | 第 6 条（不得制作传播违法信息）、第 17 条（**显著标识**） | 所有 AI 生成内容必须可识别；不得用于伪造他人身份对外交流 | 🟠 中 |
| **《生成式人工智能服务管理暂行办法》** | 第 4 条（内容合规）、第 9 条（提供者责任）、第 17 条（**舆论属性/社会动员能力者需安全评估+算法备案**） | 若做成面向公众的在线服务，需备案；纯本地单机工具通常不触发 | 🟠 中 |
| **《人工智能生成合成内容标识办法》**（2025-09-01 施行） | 显式标识 + 隐式标识（元数据） | 导出/分享的图片、音频、文本都要带标识 | 🟠 中 |
| **《数据安全法》《网络安全法》** | 数据分类分级、等保 | 若做云服务需等保测评 | 🟡 低（本地优先） |
| **未成年人保护** | 监护人同意、防沉迷 | 需年龄门槛（建议 18+） | 🟠 中 |

### 6.2 平台规则

| 平台 | 规则 | 后果 |
|---|---|---|
| 微信 | 《微信个人帐号使用规范》禁止外挂、非官方客户端、自动化操作 | 封号；**本产品 MVP 不接微信**，规避此风险 |
| QQ | 机器人协议使用需遵守平台规范 | 中风险，作为可选适配器后置 |
| App Store | 1.1.6（虚假信息/欺诈）、5.1.1（数据收集）、4.7（Mini Apps） | "模拟真人"类应用审核敏感，可能被拒；备选 TestFlight / 官网分发 / 安卓先行 |
| 国内安卓商店 | 需软著、APP 备案、隐私政策、权限说明 | 上架周期 2-4 周 |
| 支付 | 虚拟商品在 iOS 走 App Store 内购会被抽成 30%；官网/直接分发不受此限 | 影响分发方式选择（本项目为一次性买断、非订阅，倾向官网直发） |

### 6.3 境外（若出海）

- **GDPR**：聊天记录可能触及 Art.9 特殊类别数据；数据主体（前任）的访问/删除权难以履行 → **出海必须做"纯本地、不上传"架构**。
- **美国 right of publicity**：加州等州对姓名/肖像/声音的商业使用有严格限制，且**死后仍存续**。
- **EU AI Act**：Art.50 透明度义务（必须告知用户在与 AI 交互）。

## 8. 把合规做成产品（而不是免责声明）

| 合规要求 | 产品化实现 |
|---|---|
| 显著标识 | 每条 AI 消息气泡右上角常驻「AI」角标，**不可关闭**；导出内容带水印 |
| 数据最小化 | 默认全部本地；云端功能（备份/同步）默认关闭，开启需二次确认 |
| 删除权 | 设置页「一键销毁」：删除数据库、媒体、密钥、日志，30 秒内完成并给出回执 |
| 知情同意 | 首次启动 3 屏说明：数据只在你设备、对方不知情、这是模拟、不是真人 |
| 年龄门槛 | 出生年份校验，<18 直接阻断 |
| 心理安全 | 危机词检测 → 退出角色 → 提供求助热线；连续使用 90 分钟提醒 |
| 不代聊 | 无"替我回复他人"功能；无对外发送通道 |
| 声音保护 | 语音克隆 V2 需单独授权勾选 + 每次播放前显示"合成语音" |

**三条不可协商的产品红线**：
1. 不提供任何"用 ta 的账号/身份对外发消息"的能力。
2. AI 标识不可关闭、不可移除。
3. 用户数据默认不出设备。

## 9. 分发合规清单（上线前必须完成）

> **本项目定位为非营利公益项目，一次性买断（象征性定价，仅覆盖分发成本），无订阅、无内购、无广告、无数据变现。** 这一定位显著降低了商业合规负担，但**不降低个人信息与人格权方面的义务**。

- [ ] 公司/个人主体 + 软著（App 上架必需）
- [ ] 隐私政策 + 用户协议（明确"模拟""非真人""不构成心理治疗"）
- [ ] APP 备案（工信部）+ ICP 备案（官网）
- [ ] 算法备案 & 安全评估（**仅当提供在线生成服务时**；本项目无服务端、由用户自带 key 直连模型厂商，通常不构成"提供生成式 AI 服务"，需律师书面确认）
- [ ] 生成式 AI 服务相关合规自查表
- [ ] 第三方 SDK 清单与数据流图（目标：**零第三方 SDK**）
- [ ] 内容安全过滤方案（输入/输出）
- [ ] 危机干预 SOP 与求助资源库
- [ ] 数据删除与导出流程验证
- [ ] 语音克隆单独授权流程（V2）
- [ ] 不开公开募捐（避免《慈善法》适用）；自愿赞助单独说明，不在产品内诱导

## 10. 结论

1. **机会真实**：四维空位存在，且现有玩家因合规与定位原因不会轻易进入。
2. **路径清晰**：本地优先 + 单用户 + 自带模型 + 显式标识 = 合规成本可控。
3. **风险集中**：语音克隆、对外发送、云端化——**这三件事每一件都会让风险等级跳一级**，必须严格分期。
4. **非营利定位是加分项**：无服务端、无账号、无广告、无数据变现，既降低了备案与数据合规负担，也让"消费悲伤"的舆论指控失去着力点。**但这不是免责，个人信息与人格权的义务一条都不会少。**
5. **最重要的一句**：*这个产品的护城河不是模型，是"分寸"。* 分寸做对了，它是陪伴；做错了，它是二次伤害。
