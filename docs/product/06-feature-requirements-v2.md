## 1. 背景与目标

### 1.1 现状

当前项目已完成：

- 聊天记录蒸馏：导入微信/QQ/网页导出，生成人格卡、关系卡、情绪、记忆；
- 类微信聊天界面：文字、图片、语音气泡、引用/撤回、虚拟滚动、主动消息；
- 本地安全：SQLCipher、PIN、加密备份、一键销毁；
- 对话体验：关系卡、ta 状态面板、风格校准、话题上下文、聊天持久化。

### 1.2 本版目标

把产品从“能导入聊天记录并聊天”扩展为：

1. **任何人都能创建角色**：有记录用记录，没有记录用 MBTI 模板或自定义提示词；
2. **ta 能听会说**：TTS、STT、上传目标音频制作声音、可关闭的语音互动；
3. **ta 看得见**：独立于聊天的虚拟形象与桌宠；
4. **视频互动预研**：真人感数字人与虚拟形象视频通话两种路线，先做可控的虚拟形象路线；
5. **保持聊天主界面简洁**：形象、语音、桌宠、视频都是可关闭的外挂层，不改变聊天主流程。

### 1.3 非目标（本版不做）

- 手机端 / macOS；
- 文字生成 3D 模型并直接产品化；
- 默认开启摄像头、屏幕录制或后台常驻麦克风；
- 云端账号体系、社交平台自动发消息；
- 未经授权的真人声音克隆/换脸；
- 实时数字人视频作为首个正式版本承诺。

## 2. 产品原则

1. **聊天优先**：主界面仍然是微信式聊天，不新增仪表盘、侧边大面板或复杂导航。
2. **分层解耦**：聊天域、形象域、语音域、桌宠域、视频域互相独立；形象设置不能改变人格或聊天内容。
3. **所有创建方式产出一份人格**：MBTI、提示词、聊天记录都落到同一份 `PersonaProfile`，不维护三套聊天引擎。
4. **默认关闭、显式开启**：语音、桌宠、视频、屏幕感知默认关闭；开启前说明权限、费用与隐私影响。
5. **本地优先**：文字、人格、关系、记忆、聊天记录继续只存本机；云 TTS/STT/声音克隆/形象生成必须单独披露。
6. **安全边界不被形象/语音绕过**：危机干预、事实锁、关系边界、AI 披露在语音/视频中同样生效。

## 3. 用户与场景

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 没有聊天记录的新用户 | 想快速体验陪伴 | 30 秒选一个性格就能聊 |

| 纪念/哀伤场景用户 | 想保留一段关系 | 温和、不宣称“复活真人”，有危机资源 |

## 5. 详细需求

### F1 创建方式：MBTI / 性格预设

#### 用户故事

作为一个没有聊天记录的新用户，我希望选一个大致性格就能开始聊天，而不是必须先导出微信记录。

#### 需求

- F1.1 引导页提供三种创建方式：
  1. 从聊天记录创建（现有）；
  2. 选一个性格开始；
  3. 自己写一个。
- F1.2 首版提供 **8 个精选模板**，不追求 16 型全量：
  - 温柔克制、活泼黏人、理性冷静、嘴硬心软、年上照顾、年下直球、毒舌朋友、安静倾听。
- F1.3 每个模板包含：
  - 句长、语气词、表情比例、主动性；
  - 3–5 段参考对话；
  - 默认事实与说话习惯；
  - 固定安全边界。
- F1.4 选择后展示 3 句预览，可“就用这个”或“继续微调”。
- F1.5 创建完成后写入同一份 `PersonaProfile`，`origin = "preset"`；后续可编辑、回滚。
- F1.6 关系卡默认“朋友/其他”，用户可改；不自动声称是情侣。
- F1.7 文案注明“风格模板，不是心理诊断”，避免 MBTI 刻板印象。

#### 验收

- 不导入任何聊天记录，2 分钟内完成创建并发出第一条消息；
- 预设人格与蒸馏人格使用同一套聊天、情绪、记忆、主动消息；
- 不出现“必须导入记录”的阻塞。

---

### F2 创建方式：提示词/结构化人格自定义

#### 用户故事

作为一个想自己定义角色的用户，我希望用模板和字段描述 ta，而不是手写一大段不可控的 system prompt。

#### 需求

- F2.1 提供提示词模板库（温柔陪伴、毒舌互怼、年上照顾、安静倾听、朋友闲聊等），可一键套用。
- F2.2 结构化字段：
  - 身份/年龄感/职业感；
  - 与用户的关系；
  - 语气（句长、主动程度、直接/委婉、是否用表情）；
  - 口头禅/常用词；
  - 喜欢/不喜欢；
  - 边界与不能提的话题；
  - 高级：自定义 prompt 后缀（可选）。
- F2.3 安全规则（危机处理、事实锁、AI 披露）不可被自定义 prompt 覆盖。
- F2.4 保存前可预览 3 句；创建后 `origin = "custom"`，可编辑。
- F2.5 不要求用户理解 token、system prompt 或模型参数。

#### 验收

- 用户只填 5–8 个字段即可创建；
- 自定义内容不会绕过危机干预；
- 与预设/蒸馏共用运行时。

### F3 语音互动

#### 用户故事

作为一个想听 ta 说话的用户，我希望 ta 能用我熟悉的声音回复，但不想被语音打扰时可以一键关掉。

#### 需求

##### F3.1 语音总开关

设置 → 语音互动：

- **关闭（默认）**：
  - ta 不主动发语音；
  - ta 的回复不转语音；
  - 不调用 TTS；
  - 隐藏/禁用麦克风入口；
  - 聊天仍然纯文字，语音消息历史可播放。
- **开启**：
  - ta 的回复可按概率转成语音；
  - 主动消息可按概率发语音；
  - 显示麦克风按钮，可使用语音输入；
  - 用户可随时关闭，关闭后下一轮立即生效。

##### F3.2 随机语音概率

- 提供 0–100% 概率滑杆，默认 30%。
- 分别作用于：
  - 被动回复；
  - 主动消息。
- 高级设置可分开设置两个概率。
- 危机/安全提示默认 **不转语音**，优先文字与求助信息。
- TTS 失败自动降级为文字，不阻塞回复。

##### F3.3 上传目标音频制作声音

- 用户可上传对方音频（wav/mp3/m4a），要求：
  - 单人、清晰、少背景音乐/噪声；
  - 建议 10 秒–5 分钟；
  - 用户勾选“我有权使用该声音/已获得授权”。
- 流程：
  1. 上传/试听；
  2. 质量检查（时长、采样率、静音比例）；
  3. 选择本地或云端声音克隆；
  4. 生成 `VoiceProfile`；
  5. 用 3 句预览确认；
  6. 保存/删除。
- 支持预设音色作为兜底；克隆失败不影响文字聊天。
- 声音只用于本机 ta 的 TTS，不提供导出/分享/冒充他人功能。
- 声音样本与克隆 ID 存本地；云端处理需明确告知并允许删除。

##### F3.4 语音输入（STT）

- 输入框麦克风按钮，按住说话/点击开始；
- 录音 → 转写 → 填入输入框，**用户确认后发送**；
- 不做后台常驻监听；
- 支持本地 Whisper 或云 STT；
- 失败时保留录音重试/转文字。

##### F3.5 语音消息展示

- ta 的语音消息显示为语音气泡，可播放、显示时长；
- 文本转写默认折叠，可展开；
- 语音消息与文字消息使用同一套聊天流、引用、撤回、删除；
- 语音文件存本地媒体目录，数据库存路径/元数据。

#### 验收

- 关闭开关后，连续 20 轮对话与主动消息均无语音、无 TTS 请求；
- 开启且概率 100% 时，回复与主动消息均能出语音；
- TTS 失败自动出文字；
- 上传音频后可预览、可删除；
- 未勾选授权不能创建声音。

### F4 虚拟形象（与聊天分离）

#### 用户故事

作为一个喜欢视觉陪伴的用户，我希望给 ta 一个形象，但换形象不要改变 ta 的性格、记忆或聊天内容。

#### 需求

- F4.1 形象是独立对象 `AvatarProfile`，绑定 persona，但不进入聊天 prompt。
- F4.2 支持：
  - 上传图片、裁剪、圆角/背景；
  - 可选：用图片生成 API 生成 2D 头像；
  - 后续：Live2D/VRM 模型导入。
- F4.3 设置形象只影响：
  - 聊天头部头像（可选）；
  - 桌宠外观；
  - 形象页预览。
- F4.4 **不影响**：
  - 人格卡、关系卡、情绪、记忆、主动消息内容；
  - 聊天记录、模型选择、语音音色（除非用户单独改）。
- F4.5 可关闭“在聊天中显示形象”，回到文字头像。
- F4.6 文字生成 3D 模型不作为近期承诺；3D 仅支持导入 VRM。

#### 验收

- 同一人格、同一句话，在更换形象前后回复一致（随机性除外）；
- 关闭形象显示后，聊天界面与现在一致；
- 删除形象不影响聊天。

### F5 桌面桌宠

#### 用户故事

作为一个想随时看到 ta 的用户，我希望有一个独立小窗，但不想让它挤占聊天界面。

#### 需求

- F5.1 独立 Tauri 窗口，默认关闭；开启后显示在桌面。
- F5.2 基础交互：
  - 拖动位置，记住坐标；
  - 单击说一句话/冒泡；
  - 双击打开主聊天；
  - 右键菜单：隐藏、回主界面、暂停主动消息、关闭；
  - 置顶、鼠标穿透可选；
  - 多显示器/DPI 正确处理。
- F5.3 动画：
  - 待机呼吸/眨眼；
  - 说话口型或简单动效（先不做复杂口型）；
  - 拖动/被点击反馈；
  - 低性能模式：隐藏/全屏应用时暂停。
- F5.4 桌宠与聊天共用同一人格/记忆/主动消息，但不复制聊天面板。
- F5.5 屏幕感知（看视频/玩游戏并评论）作为高级可选功能：
  - 默认关闭；
  - 显式授权屏幕捕获；
  - 不做后台持续录屏；
  - 首版不做游戏内注入。

#### 参考方案对比与决策

| 参考 | 形态 | 交互感 | 成本/风险 | 结论 |
|---|---|---|---|---|
| [BV1SeHw6VEeW](https://www.bilibili.com/video/BV1SeHw6VEeW/) | Live2D 桌宠，直接显示在桌面 | 触摸/拖动/动画强，像“宠物” | 中；Live2D 授权、资源、性能 | **首版采用** |
| [BV1eAs96TEM2](https://www.bilibili.com/video/BV1eAs96TEM2/) | 屏幕陪伴型插件，能陪打电话/看视频/打游戏 | 上下文更丰富，更像“搭子” | 高；屏幕捕获、权限、兼容性、隐私 | **第二阶段可选** |

**决策：首版做 Live2D 桌宠（BV1SeHw6VEeW 路线），先保证“看得见、摸得着、低打扰”；屏幕感知作为后续“陪你看/玩”模式。**

理由：

1. 桌宠的第一感受来自直接操作与待机动画，不是屏幕理解；
2. 屏幕捕获权限重、兼容性差、容易打扰，不适合作为默认体验；
3. 首版先把桌宠窗口、拖动、气泡、主动消息打通，风险最低；
4. 后续可把 BV1eAs96TEM2 的“看视频/玩游戏并评论”作为显式开启的高级模式，而不是基础桌宠。

#### 验收

- 开启后出现独立小窗，不改变主窗口布局；
- 关闭后进程/CPU 占用明显下降；
- 拖动、点击、双击、右键、置顶、穿透可用；
- 主聊天仍可正常使用。

### F6 视频互动（两阶段）

用户提出两种方向：

| 方向 | 参考 | 特征 | 适合 |
|---|---|---|---|
| A. 真人感数字人视频 | [BV1Uq4q6dEEA](https://www.bilibili.com/video/BV1Uq4q6dEEA/) | 真人感强、实时口型/表情，视觉冲击大 | 远期差异化 |
| B. 虚拟形象视频通话 | [BV1hdHN6dETa](https://www.bilibili.com/video/BV1hdHN6dETa/) | 2D/3D 角色 + 语音，成本低、风格统一 | 先做 |

#### 需求

- F6.1 视频互动与聊天分开：
  - 聊天主窗口不嵌入视频；
  - 独立“视频通话”窗口/模式；
  - 结束通话回到聊天，不改变聊天记录。
- F6.2 首版优先 B：
  - 虚拟形象 + TTS + 口型/表情；
  - 接通/挂断、静音、网络状态；
  - 默认不录像、不保存视频；
  - 语音内容仍写入聊天记录（可选）。
- F6.3 A 作为 R&D：
  - 真人感数字人视频；
  - 需评估延迟、成本、云 GPU、肖像授权；
  - 不在首个正式版本承诺；
  - 需明确 AI 标识，禁止未经授权的真人换脸。
- F6.4 视频模式可随时关闭；关闭后完全回到文字/语音聊天。

#### 验收（B）

- 发起视频 → 看到虚拟形象 → 说话有语音/口型 → 挂断回聊天；
- 不开启摄像头也能用；
- 不默认录制/上传视频；
- 断网/超时给出明确提示。

---

### F7 Agent 与隐私

- F7.1 保持现有记忆/关系/情绪/主动消息；不新增插件市场。
- F7.2 可增加：记忆查看/删除、重要日期提醒、导出。
- F7.3 本地优先；云语音/云形象/云视频必须单独开关与说明。
- F7.4 声音克隆、真人视频必须取得授权并标注 AI 生成。
- F7.5 危机场景优先文字和现实求助资源；语音/视频不削弱安全干预。

---

### F8 UI 简洁性要求

- 主界面保持三栏聊天，不新增左侧导航项。
- 创建方式只在引导/设置出现。
- 语音默认关闭，只增加麦克风图标；语音消息复用现有气泡。
- 形象设置独立页面/弹层，不进入聊天流。
- 桌宠独立窗口，不挤占聊天。
- 视频独立窗口/模式。
- 所有高级参数折叠；关闭功能后界面回到当前样子。

## 6. 非功能需求

| 项 | 要求 |
|---|---|
| 启动 | 不因语音/形象/桌宠资源显著变慢；默认关闭时不加载模型 |
| 性能 | 桌宠隐藏时暂停渲染；TTS 不阻塞文字回复 |
| 隐私 | 聊天数据本地 SQLCipher；云端处理显式同意 |
| 安全 | 声音/形象不能绕过危机/事实锁/AI 披露 |
| 兼容 | Windows 10/11、DPI 100/125/150%、多屏 |
| 存储 | 音频/形象资源可清理；数据库可备份/销毁 |
| 可用性 | 所有新功能可一键关闭，失败自动降级 |
| 可测试 | 语音概率、开关、形象隔离有自动化测试 |

## 8. 验收指标

- 新用户无记录创建到首条消息 ≤ 2 分钟；
- 关闭语音后 TTS 请求数 = 0；
- 语音概率 100% 时回复/主动消息均能出语音；
- 更换形象前后同一人格回复语义一致；
- 桌宠开启不影响主聊天可用性，隐藏后 CPU 明显下降；
- 视频通话可挂断并回到原聊天；
- 所有云功能有明确开关、费用/隐私说明；
- 危机场景仍能给出求助资源。

## 9. 风险与待决问题

1. **声音克隆伦理**：授权、AI 标识、删除机制；是否允许非本人声音？
2. **真人感数字人**：肖像权、deepfake、成本、延迟；是否只做“风格化”而非真人复刻？
3. **屏幕感知**：录屏权限、隐私、性能；是否值得做？
4. **Live2D/VRM 授权**：Cubism SDK、模型版权、安装包体积。
5. **MBTI 刻板印象**：模板文案与心理边界。
6. **云服务成本**：TTS/STT/视频按量计费，需要预算与降级。
7. **安装包/签名**：模型与资源增大，签名/MSI/自动更新仍未完成。

## 10. 本版不做

- 手机端、macOS；
- 文字生成 3D 模型；
- 未经授权的真人换脸/声音克隆；
- 默认后台录屏/录音；
- 实时数字人视频的首发承诺；
- 社交平台自动登录/发消息。
