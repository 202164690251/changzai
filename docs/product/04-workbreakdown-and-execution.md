## 0. 一页纸结论

**1. 这个项目不是"AI 聊天 App"，是四件东西拼起来：**
`数据管道`（把聊天记录变成结构化资产）+ `人格蒸馏`（把资产变成可执行的人格） + `情绪/行为引擎`（决定怎么回、什么时候回、为什么主动） + `本地私密四端壳`（让它像当年那个窗口）。模型只是被约束的渲染器，不是产品的核心。

**2. 需要做的事分 10 条主线 + 3 条横切：**
基础设施与四端平台、数据导入、人格蒸馏、情绪引擎、对话运行时、记忆系统、主动消息、界面与体验、模型接入、安全隐私（10 条）；横切为**评测**、**合规分发**、**项目管理**（3 条）。合计可拆成 **T01–T32 + 建议新增的 14 张卡（T33–T46）+ 30 余项非代码工作**。

**3. 工作量（两套独立估算，取规划区间）：**

| 估算口径 | 乐观 | 中性 | 保守 |
|---|---:|---:|---:|
| 本文件（10 主线 + 3 横切 + 集成缓冲，含测试与联调） | 173 | 250 | 356 |
| 独立第二意见（假设工具链成熟、AI 代理承担约 60% 样板代码） | 113 | 173 | 280 |

**规划取 180–280 人日**，对应日历周期：
- 1 人 + AI 编码代理：**6–10 个月**（关键路径被 Kappa 人工标注、四端签名、审核串行卡住）
- 3 人小队（TS 全栈 + 移动/Rust + 算法数据）：**4–5.5 个月**
- 4–5 人 + 设计 + 外包法务：**3–4.5 个月**（超过 5 人不再缩短：T07 蒸馏与 T30 评测是质量瓶颈，不是人力瓶颈）
> 注意：v1.0 对话里"单人 3–5 周"的估算**不适用于 v1.1**——范围从"一个 Python 单机 demo"扩大为"四端同版本 + 情绪引擎 + 三扇门 + 撤回"，有效工作量约翻 3 倍。

**4. 精力分配与直觉相反：** 数据+蒸馏+情绪+记忆+运行时 ≈ **45%**；界面 ≈ 12%；四端平台层 ≈ 12%；评测 ≈ 6%；合规分发 ≈ 5%；集成缓冲 ≈ 12%。**先做 UI 是最大的时间陷阱。**

**5. 三个最容易被低估的工作：**
① 真实世界的导入与清洗（格式、编码、媒体过期、说话人推断）；
② 评测体系与 holdout 隔离（没有它，所有调参都是玄学——T30 放在最后是文档最大隐患）；
③ 四端打包/签名/真机测试（Tauri 2 移动端 + SQLCipher 交叉编译 + iOS 审核）。

**6. 四个必须第 1–2 周打死的 spike（否则末期同时失守）：**
① 四端空壳 + SQLCipher 交叉编译（最容易卡两周）；
② 定时通知能力——`tauri-plugin-notification` 不支持定时通知，移动端与桌面端都需原生实现（AlarmManager / UNUserNotificationCenter / 计划任务）；
③ FTS5 中文检索（默认 `unicode61` 对中文几乎无效，且 external-content 表未写同步触发器，插入不会进索引）；
④ 桌面端"关掉 App 仍有主动消息"的通道（托盘/计划任务/LaunchAgent）。
> 这四项必须在第 1–2 周给出"可行/有坑/回退"的确定性结论，并把结论写回验收口径；留到 T28 再验＝末期同时失守。

**7. 三个最大风险：**
① 盲测混淆率到不了 50%（产品证伪点，必须 Gate 1 就测）；
② 纯 API Key 是最大流失点（普通用户申请门槛，转化率可能只有 20%）；
③ 合规与分发的前置周期（软著 30–60 工作日、Apple 公司账号 2–4 周、备案、签名证书）会卡发布时间，必须第 1 周启动。

**8. 开工前必须先补的 6 个缺口（详见 §8）：**
① F04 人格修正、F08 危机/时长/出口、F15 导出迁移、F17 她主动撤回——4 项功能无任务卡；
② 事实锁运行时对抗、DoD 5"说出 5 个细节"、毕业/退出机制——三份文档反复承诺，**零任务卡、零验收**；
③ 评测集与 holdout 没有定义，T30 依赖"全部"不合逻辑；
④ 桌面端主动消息没设计（02 §9.3 只写移动端），且通知插件不支持定时；
⑤ AIGC 显式+隐式标识没有验收细则；"5 分钟导入并聊天"与微信导出现实冲突；
⑥ 8 个需要你拍板的产品决策（§8.3）。

**9. 一个必须正面解决的物理冲突：** "四端同时交付 + 5 分钟上手 + 无服务端"三者互相拉扯——全量蒸馏 17,923 条 ≈ 90 次 LLM 调用（≈12 分钟，还没算情境对与事实抽取），与 DoD 1 的 5 分钟直接冲突。解法是**两阶段蒸馏（渐进式人格）**：30 秒内先用纯统计 Style Card + 几条金句开聊，后台继续跑标注、完成后热替换人格；同时把 DoD 1 的计时终点从"导入开始"改成"已有人格开聊"（建议新增 T44）。

**10. 最快的证伪路径：** 第 1 周做四个 spike + 数据导出；第 2–4 周做数据管道与两阶段蒸馏，用封存的 300–500 条真实回复跑盲测。**盲测 <40% 就停，别碰 UI。** 这是唯一能提前杀死错误方向的实验。

## 1. 项目本质与不可让渡的约束

### 1.1 一句话与三层价值

> 把一段关系，做成一个还愿意陪你说说话的人。

| 层 | 用户感知 | 对应的工程 |
|---|---|---|
| L1 熟悉 | "语气对了" | Style Card + 情境-反应对 + AI 味过滤 |
| L2 沉浸 | "她就是这样" | 情绪引擎 + 节奏（延迟/分段/已读） |
| L3 被接住 | "聊完轻了一点" | 情绪弧线 + 和解路径 + 安全阀 + 出口 |

**护城河在 L3，不在 L1。** 语气可以被抄，情绪分寸抄不走。

### 1.2 六条不可让渡的设计约束（违反任何一条都要推倒重来）

| # | 约束 | 来源 | 对工作内容的影响 |
|---|---|---|---|
| C1 | 数据默认不出设备，无服务端、无账号、无遥测 | 01 §8、03 §10 | 所有能力必须本地实现；没有"云端兜底"这条路 |
| C2 | 四端同版本、同功能、同时交付 | 00 §一页纸、02 §12.5 | 平台层成本 ≈ 独立一条主线；移动端限制反向约束产品设计 |
| C3 | 纯 TS + Tauri 2，不引入 Python/本地模型 | 02 §1 | 算法要全部翻译成 TS；唯一回退路径是换壳 Capacitor |
| C4 | 只支持用户自带 API Key（OpenAI 兼容） | 02 §10、03 §7 | 模型接入层做薄；但"怎么让用户拿到 key"要做厚（产品工作） |
| C5 | 三条安全律（归因/上限/出口）+ AI 标识不可关闭 | 01 §8、02 §6.6 | 不是免责声明，是代码级硬约束 + 不可绕过的 UI |
| C6 | 事实锁 + 关系悬置，拒绝迎合 | 02 §5.5/§6.7、03 §2.2 | 需要独立的对抗测试集，不是一句 prompt 能保证 |

### 1.3 成功的定义（从文档中抽取，作为最终验收）

- DoD 10 条（02 §17）全部成立；
- 指标：盲测混淆率 ≥50%（MVP）、情绪收益（平静度）+1.5、负向放大率 <5%、5 分钟内首次对话、四端同版本跑通；
- **明确不看**：DAU、使用时长、消息数（03 §11）。看这三个指标做决策，产品一定走歪。

## 3. 工作分解（WBS）：10 条主线 + 3 条横切

> 每条主线给出：**要做什么 / 关键难点 / 主要产出 / 验收口径 / 对应任务卡 / 估算（乐观-中性-保守，人日）**。
> 估算假设：有经验工程师、含自测不含返工、AI 编码辅助按 1.5–2.5× 提效后折算；不含外部等待（审核/备案/证书）。

### 3.1 主线 A · 基础设施与四端平台层（30 / 12%）

**要做什么**：pnpm monorepo + Turbo；Tauri 2 四端初始化；Rust 侧命令（db / fs / keychain / notify / http / path）；SQLite + SQLCipher 封装与迁移；CI；四端打包、签名、公证、测试分发；崩溃/日志脱敏。

**关键难点**：
- `bundled-sqlcipher` 在四大平台的交叉编译（Android NDK / iOS Xcode / Windows MSVC / macOS）；
- Keychain：`keyring` crate 在移动端能力有限，可能需要自写 plugin 或 stronghold；
- Tauri 2 移动端成熟度（插件生态、权限、后台限制）；
- 四端行为一致性（同一份 UI 与 core，平台差异只能进 Rust 适配层）。

**产出**：可启动的四端空壳、加密 DB、迁移机制、签名安装包、CI 流水线、平台能力矩阵文档。

**验收**：四端 `dev` 均可启动；加密库读写通过；干净机器安装即用（T28）；`core` 内零 `window/fs/fetch/localStorage`（ESLint 规则）。

**任务卡**：T01、T02、T28（部分）、T32（通知部分）。**技术 spike 需前移到第 1 周**（见 §8.1 新增 T40）。

**估算**：22–30–42 人日（其中打包签名/四端真机占 1/3 以上）。

### 3.2 主线 B · 数据导入与体检（16 / 6.4%）

**要做什么**：插件式适配器框架；5 个格式（wechatmsg_txt / wechatmsg_csv / liuhen_json / qq_txt / plaintext_paste）；编码探测；时间戳正则族；说话人判定（显式字段 → 缩进/前缀 → LLM 兜底）；系统消息分类；burst 识别（<90s）；latency 计算（截断 86400）；去重；媒体资产预留（P1 落库）；数据体检报告（含还原度估算 0–100 与三档模式）。

**关键难点**：
- **真实数据永远比文档脏**：微信导出格式随版本变、缺 sender、时间戳本地时区、跨设备与跨年的记录拼接；
- 说话人推断错误会污染整个人格（比没有数据更糟）；
- 媒体导出链路由外部工具完成，产品必须做"向导 + 校验 + 缺口提示"，而不是假装能一键；
- 还原度公式是启发式（02 §4.4），需要拿真实数据校准，否则报告会误导用户。

**产出**：归一化 JSONL schema（含 latency/burst/reply_to）、适配器注册表、体检报告 JSON + UI、导入失败的可操作提示。

**验收**：3 种格式各 1000 条无异常；burst/latency 与人工抽检 30 条一致率 >90%；报告字段齐全、fidelity 分档合理；5 万条冷启动 <90s。

**任务卡**：T03、T04、T05。**估算**：12–16–22 人日。

### 3.3 主线 C · 人格蒸馏（21 / 8.4%）

**要做什么**：情绪标注（20 条窗口、200 条/请求、24 标签枚举、失败重试/跳过）；人工抽检 200 条算 Cohen's Kappa（<0.6 不得上线情绪引擎）；Style Card 纯统计（句长分位、burst、标点比、emoji、2–4gram 口头禅 + PMI、typo、语音比、夜间比、延迟对数正态、开场白、称呼演变）；Episode 切分（时间 + 话题）；情境-反应对抽取（证据链强制，无证据丢弃，30–60 条取 top40，冲突保留）；事实抽取 + Fact Lock（confidence<0.6 不入锁、关系状态 suspended）；产物 6 件套 + 人类可读报告。

**关键难点**：
- 标注质量决定情绪引擎上限——LLM 标注必须先校准再用（Kappa 是硬门）；
- 情境-反应对要"可执行"而不是形容词，证据链是防幻觉的唯一办法；
- 事实锁需要"抽取 → 冲突检测 → 拒绝改写"三段闭环，单纯抽取不够；
- 蒸馏是一次性成本，但重跑很贵 → 需要断点续跑、幂等、增量 diff 设计。

**产出**：`prompts/label_emotion.md`、`prompts/extract_pairs.md`、`prompts/extract_facts.md`、style_card.json、persona_graph.json、facts.json、memories.jsonl、baseline.json、report.md。

**验收**：1000 条标注成功率 >98%；Kappa ≥0.6；每 persona ≥30 条情境对且无证据条目为 0；抽 20 条事实人工准确率 >85%。

**任务卡**：T06–T11。**估算**：15–21–30 人日（含人工标注 2–3 人日）。

**审计补强**：
- `persona_graph.json`、`baseline.json`、`report.md` 与 `layer0_hard_rules` 在 02 §5.6/§7.4 是产物，但任务卡里没有一张负责产出与验收——需并入 T10/T11；
- **T07 是全项目的单点阻塞**：200 条人工标注没有人力来源、标注手册与第三方复核，"Kappa ≥0.6" 无判分人；必须在 W1 就确定标注人、写手册、双人复核，否则 T10/T12/T13 全部排队等它；
- Correction 层（用户改人格）在 DDL 里没有表（`feedback` 语义不同），需新增 `correction` 表或明确复用方案。

### 3.4 主线 D · 情绪引擎（19 / 7.6%）

**要做什么**：四轴状态（valence/arousal/closeness/defensiveness）+ weather + tension；惯性衰减（向 baseline 回归，half-life 180 分钟）；单轮最大变化硬限（|Δv|≤0.35、|Δc|≤0.3）；刺激→情绪转移矩阵（3×3 网格 × 8 类刺激）；表里差抑制模型（依恋类型 + 关系安全度 + 负面加成）；张力池与爆发（>0.72 → storm → 回落）；Arc Director 四类场次 + 温度预算 + 强制转向；Comfort Governor 三律 + 脆弱度六信号。

**关键难点**：
- 情绪是**状态**不是标签：所有效果必须可解释（哪个 appraisal 导致了哪个 delta）；
- 转移矩阵需要足够的历史标注量，小样本会过拟合 → 需要平滑/回退到默认参数；
- 表里差（嘴硬）是"像人"的核心，但过度抑制会让用户觉得"冷暴力" → 需要与安全阀联动调参；
- Governor 是产品命门：误杀会让对话平淡，漏放会伤人，阈值只能靠内测数据调。

**产出**：情绪状态机、转移矩阵、Arc Director、Governor、脆弱度评分、对抗样例集（20 条）。

**验收**：单测覆盖 4 轴边界与惯性；4 类场次各 10 轮回放通过；20 个对抗样例全部拦截；单轮变化不越界。

**任务卡**：T12–T15。**估算**：13–19–26 人日。

**审计补强**：
- 律三"3 轮内递台阶"（DoD 4）只有拦截验收，没有出口行为验收；"3 轮"的计数口径（用户轮/消息轮/跨会话是否重置）需写死；
- §6.6 的脆弱度评分依赖"单日使用 >120 分钟"，但时长监测在 03 属 P1——**F08 依赖一个未排期功能**，需前移一个"会话时长埋点"小卡；
- 温度预算与律二软化同时触发时的优先级未定义，需在 T14/T15 里裁定。

### 3.5 主线 E · 对话运行时（24 / 9.6%）

**要做什么**：五步流水线（Appraise → Decide → Compose → Filter → Emit）；Appraise JSON（话题/情绪/强度/关系信号/禁忌/张力增量）；Decide（回复概率 0.92×清醒度×兴趣、对数正态延迟 × busy × mood、burst 采样、emoji/语音决策、已读不回）；Compose（Layer0 硬规则 + Style Card 硬约束 + expressed 情绪 + Arc 预算 + 3–5 组 few-shot 情境对 + 记忆 3–6 条 + 最近 12 轮，流式输出）；AI 味过滤器 8 条规则；一致性检查；Safety filter；Emit（typing + 分段节奏 + 抖动）；撤回重发（recalled=1、上下文/记忆彻底剔除、负例入库、防滥用 3/20 条、10/日、她也 3% 主动撤回）；撤回后重发不重复。

**关键难点**：
- Prompt 组装与 token 预算的稳定性（<3000 tokens 记忆 + 12 轮 + few-shot）；
- 流式 + 分段 + typing 的竞态（用户中途输入、取消输入 8%）；
- 撤回必须穿透所有缓存层（上下文/摘要/记忆/情绪归因），任何残留都会"露馅"；
- 只输出她会说的话（无旁白、无动作、无破折号）需要输出解析器 + 重试策略。

**产出**：`prompts/appraise.md`、`prompts/compose.md`、运行时状态机、AI 味过滤器（含单测）、Emit 编排、撤回 API + UI 交互。

**验收**：首 token <2s（视用户 API）；分段符合 burst；过滤器 50 条样例误杀率 <10%；撤回后旧句在任何上下文中不可检索；重发不重复。

**任务卡**：T20–T22、T31。**估算**：17–24–33 人日。

**审计补强**：
- 每轮实为 **3 次 LLM 调用**（appraise + compose + rerank），用户以为"一次聊天一次钱"——设置页要显示调用次数/成本，appraise 可降级为本地规则（关键词+长度+问号）作为省钱档；
- T25 验收"端到端 <3s"与 02 §7.3 拟人延迟 `clip(delay, 3, 7200)` 冲突（首条就 ≥3s）——改为"首 token <2s（不含拟人延迟）+ 决策后出字 <300ms"；
- T31 依赖漏项：`memory.exclude` 属 T16/T17 范围；撤回还需验证"再聊 5 轮后旧句仍不出现"（只测即时状态不够）。

### 3.6 主线 F · 记忆系统（16 / 6.4%）

**要做什么**：四层记忆（L0 近 20 轮原文 / L1 情节摘要 + 未闭合话题 / L2 原话片段 + 事件 / L3 关系状态）；FTS5 BM25 召回 + 情绪一致加权 + 时间衰减 + 重要性 + 可选向量 RRF + LLM 重排（fast 模型）；遗忘曲线（只对 importance<0.6 的次要细节，事实锁永不衰减）；未闭合话题生命周期（open/resolved/expired，7 天）；上下文装配与 token 预算。

**关键难点**：
- **FTS5 默认分词对中文不友好**（unicode61 实际按空格切），必须早验证 trigram / 自定义分词方案，否则检索形同虚设——这是文档未写但大概率踩的坑；
- 情绪一致检索（用户难过时优先召回"她安慰过你"）需要记忆条目带情绪标签，依赖标注质量；
- 遗忘的"表演层"（偶尔记不清细节）要可控，记错共同经历会直接出戏；
- 未闭合话题检测准确率决定主动消息质量。

**产出**：检索接口、记忆装配器、遗忘任务、open_loop 检测器、token 预算控制。

**验收**：top5 相关率人工评估 >70%；注入 token 可控（<3000）；10 个样例 open_loop 正确识别 ≥8；事实类记忆零衰减。

**任务卡**：T16–T18（若做向量检索再加 P1 卡）。**估算**：11–16–23 人日。

**审计补强**：
- `memory_fts` 未指定 tokenizer、未写 `AFTER INSERT/UPDATE/DELETE` 同步触发器——**中文检索会静默失效**且不报错，必须在 T02 就用 1000 条中文记忆 + 50 条查询做 recall@5 验证；
- T17"注入 <3000 token"与 L0"最近 20 轮全量"在长对话下必然冲突，需定义截断/摘要降级策略；
- §8.3 遗忘曲线（`mark_as_faded`、永不衰减白名单）没有任务卡承接，需并入 T17。

### 3.7 主线 G · 模型接入层（7 / 2.8%）

**要做什么**：`LLMProvider` 统一接口（chat 流式、embed 可选）；`OpenAICompat`（7 家预设 + 自定义 base_url）；角色路由（main/fast/embedding，默认自动降级）；重试与失败处理（401/403 不重试、429 指数退避 + 备用模型、5xx 重试 2 次、内容拒绝降级话术、>30s 超时提示"她好像没看到"）；Key 安全（Keychain、不落库、日志脱敏、导出排除、截图遮蔽）；测试连接（"通了"）。

**关键难点**：
- 各家"OpenAI 兼容"的兼容程度不同（JSON mode、流式格式、错误码、base_url 拼接）；
- 流式取消与超时的资源回收；
- **这不是技术难点，是产品难点**：让普通用户拿到并配置 key（见 §7 风险 R6）。

**产出**：适配器、预设表、路由与降级、Key 存储、测试页、7 家申请教程。

**验收**：3 家 provider 跑通流式；无本地推理依赖；换模型人格资产不丢。

**任务卡**：T19、T27。**估算**：5–7–10 人日。

**审计补强**：
- "3 家 provider 跑通"未指定哪 3 家，也未验 §10.5 的 401/429/5xx/拒答/超时五类失败分支；DoD 6"换模型人格不崩"没有任何回归测试卡（建议并入 T30b：50 条输入 × 3 模型比对风格距离）；
- Key 存储两套方案（§10.4 `stronghold` vs §12.5 `keyring`）必须二选一写死，否则 T19/T29 各做一套。

### 3.8 主线 H · 主动消息（12 / 4.8%）

**要做什么**：欲望×机会模型（share / followup / missing / ritual / repair 五类欲望）→ 阈值入队 → Governor 复核 → 预算（日 3、周 12、免打扰 23:30–08:00、连续未回降频、3 天暂停）→ reason 可读 → 预生成 + 定时投递（移动：本地通知；桌面：待定，见 §8.1 T38）→ 点通知直达会话。

**关键难点**：
- "来由"必须真实可读，否则就是骚扰；每条主动消息都要能解释；
- 移动 OS 杀后台 → 预生成 + 本地定时通知；但 iOS 本地通知条数与时间精度有限，需验证；
- 桌面端关闭 App 后无法投递 → 产品形态决策（托盘/自启/打开补发）；且 `tauri-plugin-notification` 不支持定时通知，移动端 T32 也需原生实现（Android AlarmManager / iOS UNUserNotificationCenter）——这是一张隐藏的"原生插件卡"；
- 反成瘾设计：禁止不可预测奖励（老虎机），频率可预期可关。

**产出**：主动队列、预算器、通知调度、预生成流水线、reason 展示。

**验收**：7 天模拟不超预算；reason 可读；杀进程后移动端仍按时收到（T32）；3 天未回复自动暂停。

**任务卡**：T23、T32。**估算**：8–12–17 人日。

### 3.9 主线 I · 界面与体验（31 / 12.4%）

**要做什么**：仿微信交互语言的聊天壳（不复刻商标素材）；虚拟滚动消息列表、时间分隔、文本/图片/语音气泡、系统提示、typing 三点（可被取消）、流式打字机、分段到达、已读、长按菜单（复制/引用/撤回/删除）、撤回动画、下拉"那年今天"；AI 角标（不可关闭/不可被样式覆盖）；三扇门入口（日常/回忆/深夜）；4 步引导（三屏说明 + 年龄校验 → 导入 → 体检报告 → 人格卡审阅 → 模型配置）；模型设置页；人格卡与纠正页；安全页（危机资源/时长/退出）；设计 token（颜色/字号/圆角/气泡 70%/头像 40px）；文案规范（不用感叹号、"她好像没看到"）。

**关键难点**：
- 拟人节奏的一半来自前端（typing、分段、抖动、取消），这些是状态机不是动画；
- 移动端输入法/长按/震动/安全区适配；
- 人格卡审阅要"用户改完立即生效"（Correction 层），不是展示页；
- 撤回、引用、删除与消息状态的组合态很多，需要严格状态机。

**产出**：组件树、设计 token、交互验收清单 8 条、引导流程、设置页、安全页、文案表。

**验收**：与设计稿像素差 <2px；新用户（已有导出文件）5 分钟内发出第一条消息；8 条拟人细节逐条验收；AI 标识任何主题下可见。

**任务卡**：T24–T27。**估算**：22–31–43 人日（设计另计 15–25 人日，可在估算外按外包/兼职计）。

**审计补强**：
- T24 验收"与设计稿像素差 <2px"但全仓没有设计稿（只有 token 表），不可判定——W8 前必须冻结高保真设计稿，否则该卡无法验收；
- "语音条"在 03 §6.2 是 P0 验收、在 03 §5 是 P1，建议移到 P1，否则 F05 的 8 条验收永远有一条过不了；
- "已读"与 30–90 分钟补话依赖 T22/T23，T24 的任务依赖需补上。

### 3.10 主线 J · 安全与隐私（9 / 3.6%）

**要做什么**：SQLCipher 加密（密钥 Argon2id 派生 + Keychain）；启动锁（PIN/生物识别，可选）；一键销毁（db/media/keychain/缓存，覆写 2 次，30 秒内，回执）；日志脱敏与默认关闭；网络白名单（只允许用户配置的 endpoint）；导出二次确认 + 风险提示；无遥测；AI 标识（显式角标 + 导出水印 + 隐式元数据）；卸载提示 key 仍在钥匙串并提供清除入口。

**关键难点**：
- "销毁"要能被验证（DoD：硬盘上找不到任何聊天内容）——需要测试方法与回执设计；
- 隐式标识（《AI 生成合成内容标识办法》要求元数据）在图片/文本导出中的落地；
- Key 与日志是最容易泄漏的两处。

**产出**：加密与销毁、AI 标识组件与导出流水线、日志策略、白名单、安全测试报告。

**验收**：销毁后数据不可恢复；导出内容带标识；日志无明文姓名/手机号；AI 角标不可关闭。

**任务卡**：T29（+ 建议 T37 标识卡）。**估算**：6–9–13 人日。

**审计补强**：
- "销毁"的覆盖面不足：缺 `-wal`/`-shm`、FTS 影子表、`media/`、`logs/`、Keychain 残留项、系统/iCloud/Time Machine 备份副本；"30 秒"计时也没有验收；
- SSD/闪存的 wear-leveling 让"覆写 2 次"基本无意义——**文案应从"不可恢复"改为"已从本机删除"**，否则被媒体实测打脸是信任崩塌；
- DoD 7 需定义取证方法：销毁前后用 `strings` 搜独特测试语、`PRAGMA freelist_count` 检查残留页，并明确"硬盘"范围。

### 3.11 横切 K · 评测体系（13 / 5.2%）

**要做什么**：
- **Holdout 隔离**：从导入数据里封存 300–500 条她的真实回复（含上下文），**绝不进入蒸馏/检索**，否则混淆率虚高；
- 回放测试：200 条真实对话逐条输入引擎，比较语义相似度与风格距离；
- 黄金集：50 个情境 → 期望反应类型（不比文本比类别）；
- 盲测 harness：300 条真实回复 + 300 条生成回复随机混排，人/AI 判定，输出混淆率与置信区间；
- 情绪收益：会话前后 1–10 分自评（孤独/难过/平静），目标平静 +1.5；
- 负向放大率：聊完更难受的比例 <5%；
- 出戏点记录与周迭代；
- 内测协议（知情同意、可退出、危机转介）。

**关键难点**：这是最容易被拖延、也最影响正确性的工作；数据隔离与伦理必须一开始就设计。

**产出**：harness、holdout 集、黄金集、盲测报告、情绪问卷、内测 SOP。

**验收**：能一键跑回放与盲测并出报告；每次改 Prompt 可回归；指标可追溯到具体改动。

**任务卡**：T30（建议拆成 **T30a 第 2 周建最小 harness / T30b 第 14 周做正式评测**）。**估算**：8–13–19 人日。

**审计补强**：
- holdout 切分没有责任卡（`is_holdout` 字段存在但无人负责），一旦蒸馏用了全部数据，盲测分数就是自欺——在 T04/T30a 里写死"谁切、何时冻结、如何校验"；
- 没有回归网：改一句 `compose.md` 无人跑评测。W4 就要有 `pnpm eval`（50 条黄金集 → 反应类别 + 风格距离 + 禁用词命中），纳入 CI；
- 内测数据涉及第三方（前任）隐私，需知情同意与去标识流程。

### 3.12 横切 L · 合规、法务与分发（13 / 5.2%）

**要做什么**：
- 文档：隐私政策、用户协议（明确"模拟""非真人""不构成心理治疗"）、AI 标识说明、数据处理说明、第三方 SDK 清单与数据流图（目标零 SDK）；
- 主体资质：公司/个人主体、软著、APP 备案、ICP 备案、算法备案与安全评估判定（律师书面确认是否需要）；
- 年龄门槛：18+ 声明 + 出生年份校验；
- 心理安全：危机词 SOP、求助资源库、90 分钟提醒、毕业机制；
- 分发：GitHub Releases + 官网（Win/macOS/Android 直发）、iOS TestFlight、商店素材与截图合规、买断定价（若收费，iOS 数字商品需 IAP，30% 抽成 → 更倾向官网直发）；
- 开源：协议选择（建议 AGPL-3.0 客户端）、仓库治理、开源前 prompt/样例脱敏审计；
- 成本：Apple $99/年、Windows 签名 ¥1–2k/年、域名 ¥100/年、服务器 ¥0。

**关键难点**：全部有**前置周期**（软著 30–60 工作日、APP 备案 2–4 周、Apple 公司账号 2–4 周、审核 1–2 周、证书 1–2 周），必须第 1 周并行启动；其中律师对"是否构成生成式 AI 服务"的书面结论是唯一可能让架构返工的外部输入，必须第 1 周先拿方向性意见。

**产出**：法务文档包、备案材料、商店素材、分发清单、危机 SOP。

**验收**：清单 01 §9 全部打勾；律师确认算法备案适用性；App 内 4 处合规文案到位。

**任务卡**：文档未列 → 建议新增 **T41 合规定稿**、**T42 分发与发布**。**估算**：8–13–20 人日（不含外部等待与律师费）。

### 3.13 横切 M · 项目管理与集成（30 / 12%）

**要做什么**：需求变更控制（§2.2）、每周 Gate 评审、跨模块联调、缺陷修复、真机测试矩阵、发布候选管理、风险登记册维护、文档同步。

**验收**：每周有可运行产物；Gate 有明确通过/终止标准；缺陷收敛曲线可控。

**估算**：约为主线的 15–20%，取 20–30–45 人日。

### 4.1 按里程碑归组（把 32 张卡变成 5 个可验收的 Gate）

### 5.3 用户侧 API 成本模型（公益定位的关键，必须写进引导页）

> 假设：国产模型（DeepSeek/Qwen 级）约 ¥2/百万 input、¥8/百万 output；海外旗舰约 20–50 倍。以下为量级估算，非报价。

| 场景 | 单次消耗 | 成本（国产） | 成本（海外旗舰） |
|---|---|---|---|
| 一次性蒸馏（她的消息 1.8 万条 + 上下文） | 约 30–90 万 input / 15–30 万 output 等效，多次调用 | **¥50–300** | ¥1,000–5,000 |
| 日常每轮（Appraise + Compose + Rerank） | 约 6k input + 300 output | **¥0.01–0.03/轮** | ¥0.2–0.6/轮 |
| 每天 100 轮 | — | ¥1–3/天 | ¥20–60/天 |
| 重度用户每月 | — | **¥30–90** | ¥600–1,800 |
| 主动消息 3 条/天 | 极低 | <¥1/月 | ¥5–15/月 |

**结论**：国产模型中，用户月账单约 ¥20–100，可接受；必须做"成本估算器"并在配置页提示，否则会被投诉。**"首次蒸馏可能花掉几十元"这件事必须在导入前告知**，这是预期管理的一部分。

**两个必须写进验收的成本/延迟事实**：
- 每轮对话是 **3 次调用**（appraise + compose + rerank），不是 1 次；appraise 可降级为本地规则以省钱；
- DeepSeek 首 token 常在 1–3s，加拟人延迟后，02 §15.3 的"首 token <1.5s"多数达不到——建议改为"首 token <2s（不含拟人延迟）"。

### 8.4 三条架构级补丁（建议先写回 02，再开工）

1. **渐进式人格（T44）**：把"蒸馏完成才能聊"改成"先聊起来、后台升级人格"。这是让 DoD 1（5 分钟）与全量蒸馏能同时成立的唯一办法；同时它天然解决"用户等 12 分钟就关闭 App"的流失。

3. **本地可观测性（T45）**：无遥测是对的，但没有观测就无法证明"负向放大率 <5%"，也无法发现回归。用"本地埋点 + 用户可查看/可删除 + 匿名贡献默认关闭"折中，别在"隐私"和"瞎调"之间二选一。

## 附录 C · 关键术语

- **盲测混淆率**：人（或强模型）在"真人回复 vs AI 回复"二选一中分不清的比例，本项目的核心真实感指标。
- **holdout**：从导入数据中封存、绝不参与蒸馏/检索的真实回复，用于公平评测。
- **事实锁 / 关系悬置**：既定事实不可改写；"已分手"这一状态被悬置（不主动提、不否认）。
- **表里差**：内部情绪与表达情绪之差，即"嘴硬"的量化。
- **温度预算**：一场对话允许使用的负面强度上限，耗尽强制转向。
- **Comfort Governor**：归因/上限/出口三律的实现，不可关闭。
- **未闭合话题（open loop）**：她问过但用户没答的问题/约定，是主动消息最高回复率的燃料。
- **还原度（fidelity）**：由她的消息量、时间跨度、夜间比、冲突段、语音等加权的 0–100 启发式评分，决定轻度/标准/高保真三档。
