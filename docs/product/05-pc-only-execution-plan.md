# 05 · PC 单端执行方案（Windows 优先）

> 项目代号：**常在（Still Here）**
> 前提：**本期只做 PC 端软件（聊天系统 + 其余全部产品功能），暂不适配手机 / 平板。**
> 依据：`00`–`03`（v1.1）、2026-11-09 会话记录、`04-workbreakdown-and-execution.md`（四端基线）
> 结论先说：**去掉的是"移动端平台适配与移动分发"，不是产品能力。** 核心工作量（数据、蒸馏、情绪、记忆、运行时、界面）几乎不变；但四端风险、审核链路、真机测试大幅下降，主动消息反而变简单。**建议按 7 步、16 周（3 人 + AI 编码辅助）推进；单人 + AI 约 6–8 个月。**

**七个步骤（每步都有可验收产物）：**

| 步 | 名称 | 周期（3 人+AI 参考） | 核心产出 | 门 |
|---|---|---|---|---|
| Step 0 | 决策与准备 | 2–3 天 | 范围/平台基线/证书/数据导出/holdout | — |
| Step 1 | 技术底座 + 5 个 spike | 第 1 周 | 能跑的 Windows 桌面壳 + 五项能力结论 | **G0** |
| Step 2 | 数据管道 | 第 2–3 周 | 5 适配器 + 体检报告 + 媒体导入 | — |
| Step 3 | 人格蒸馏 | 第 2–4 周（并行） | Style Card / 情境对 / 事实锁 / 可编辑人格卡 | **G1 盲测 ≥40%** |
| Step 4 | 情绪引擎 + 记忆 | 第 4–6 周 | 四轴状态机 / 弧线 / 安全阀 / 四层记忆 | — |

| Step 6 | 界面 + 引导 + 安全 + 打包 | 第 8–12 周 | 仿微信壳 / 4 步引导 / 安装包（签名） | **G3 可安装** |
| Step 7 | 评测 + 内测 + 发布 | 第 12–16 周 | 盲测报告 / 内测 / 官网与更新 | **G4 发布** |

**五个必须在第 1 周打死的 PC 版 spike：**
① SQLCipher（Windows/MSVC）能否稳定构建与打开；② FTS5 中文分词（trigram）召回是否可用；③ 托盘常驻 + Windows 通知是否可靠；④ Rust 侧 HTTP 流式调用能否稳定出字；⑤ 未签名 `.msi` 能否在干净 Win10/11 安装并启动（WebView2 是否缺失）。
> 任何一项失败，回退方案在 Step 1 里写死（见 §3 Step 1），不要拖到 UI 做完才发现。

**PC 单端最大的三个"变简单"：**
1. **主动消息**：桌面进程可以常驻托盘，用进程内定时器 + 即时 Windows 通知即可，不需要移动端"预生成 + 系统定时通知"那套原生插件（原 T32 直接删除）；关掉窗口仍能收到，完全退出时下次启动补发。
2. **四端一致性/交叉编译**：iOS/Android 的 NDK、Xcode、Keychain/Keystore、移动 UI 适配、TestFlight 全部消失。
3. **发布**：GitHub Releases + 官网直发，不需要商店审核，迭代可以按天走。

**PC 单端最大的三个"没变简单、反而更显眼"：**
1. **数据导入仍是最大流失点**（微信导出要 PC + 第三方工具）——PC 端反而有优势：用户就在电脑前，可做"导入向导 + 一键检测 + 图文视频教程"。
2. **人格蒸馏仍是上限**（Kappa、情境对、事实锁），与端无关。
3. **评测仍是唯一证伪手段**（holdout + 盲测），必须在 Step 3 就开始，不能再拖到最后。

### 1.3 "PC 端"平台基线（Step 0 必须拍板）

| 决策 | 建议默认 | 理由 |
|---|---|---|
| 操作系统 | **Windows 10 1809+ / Windows 11 x64** | 用户基数最大；WebView2 基本预装 |
| macOS | 同代码库保留可构建，**本期不出包**（或出未公证 dmg 内测） | 需 Apple 账号 + 公证，非阻塞项 |
| 安装包 | `.msi`（主）+ `.exe`（便携/备用） | 自分发友好；MSI 可做升级 |
| 运行时 | Tauri 2 + WebView2（Evergreen） | 与 04 一致；包体小、内存低 |
| 数据目录 | `%APPDATA%\StillHere\`（DB/media/logs） | 符合 Windows 习惯；卸载不自动删数据 |
| 常驻形态 | 关闭窗口 → 最小化到托盘（可在设置里改为"直接退出"） | 主动消息的前提 |
| 开机自启 | **默认关闭**，设置里可开 | 尊重用户；开启后主动消息体验最好 |
| 更新 | 首版手动下载；V1.1 起加自动更新（签名密钥离线保管） | 先跑通再自动化 |
| 代码签名 | **买 OV 证书**（¥1–2k/年，1–2 周） | 否则 SmartScreen 拦截，是 PC 端最大的"第一印象杀手" |

### 1.4 未来补移动端的代价（决定本次架构纪律）

本期仍保留 `packages/core` 纯 TS、平台能力全部走注入接口、数据格式带版本号。这样未来补 Android/iOS 只需：Tauri 移动壳 + 平台适配层 + 通知/钥匙串/文件选择插件，预计 **4–6 周 + 签名审核**，不需要重写核心。**不要为了"先快"把逻辑写进 UI 或直接调 `fs`/`fetch`**，这是唯一会毁掉未来选项的做法。

## 3. 分步执行（Step 0–7）

> 每一步都写清：**做什么 / 产出 / 验收（可判定）/ 失败怎么办 / 参考人日**。
> 任务卡编号沿用 02 §14 与 04 §8.1；"T28-PC"表示 PC 版改造。

### Step 0 · 决策与准备（2–3 天，W0）

**目标**：把"只做 PC"变成一份可执行的基线，避免做到一半改平台。

**要做的事**：
1. **S0-1 冻结范围**：本期 = Windows 桌面 + 全部产品功能；移动端/商店/云同步列入非目标。
2. **S0-2 定平台基线**：§1.3 的 9 个决策逐条拍板（OS 版本、安装包、数据目录、托盘、自启、更新、签名、macOS 出不出包）。
3. **S0-3 证书与账号**：下单 Windows OV 签名证书（1–2 周）；开 GitHub 仓库 + 官网；如需 macOS 再开 Apple 账号。
4. **S0-4 数据到手**：用自己的 Windows 微信 + 导出工具，确认文字/图片/语音能导出；脱敏；异地备份原始数据。
5. **S0-5 封存 holdout**：随机抽 300–500 条她的真实回复（含前后文）单独存，**绝不进入蒸馏与检索**。
6. **S0-6 冻结设计**：至少聊天主界面 + 4 步引导 + 设置页的高保真稿与 token（02 §12.2），否则 T24 的"像素差 <2px"无法验收。
7. **S0-7 拍板产品问题**：04 §8.3 的 8 个问题 + PC 特有 3 个（托盘默认？开机自启默认？是否本期出 macOS 包？）。

**产出**：一页《PC 单端范围与决策记录》；可解析的导出文件；封存的 holdout；证书订单；设计稿 v0。
**验收**：上述 7 项都有明确文件/账号/订单；任何人问"这个功能为什么不做"能在记录里找到答案。
**失败怎么办**：数据导不出来 → 立刻做"纯手工描述"降级路径（10 个问题生成基础人格），不要卡在导出上。
**参考人日**：3–5。

### Step 1 · 技术底座 + 5 个 spike（第 1 周）→ Gate G0

**目标**：用一周证明"这台 Windows 电脑上，这套技术能跑"，而不是等 UI 做完才发现。

**要做的事**：
1. **T01-PC**：pnpm monorepo（`apps/app` + `packages/core` + `packages/shared`）+ Tauri 2 **桌面**初始化 + React/Vite/TS/Tailwind + ESLint 规则（core 禁 `window/fs/fetch/localStorage`）。
2. **T02-PC**：SQLite + SQLCipher（MSVC）+ 迁移机制 + 加密密钥（Argon2id + Windows 凭据管理器）+ 单测。
3. **T40-PC 五个 spike**（每个 0.5 天内出结论，写成一张表）：
   - SQLCipher：建库/写 1000 条/读/重启后能否打开；`strings db` 搜不到明文；建库耗时。
   - FTS5 中文：建 1000 条中文记忆 + 50 条查询，对比 `unicode61` vs `trigram` 的 recall@5；补外部内容表同步触发器。
   - 托盘 + 通知：关窗最小化到托盘；发一条 Windows 通知；点击回到窗口。
   - Rust 侧 HTTP 流式：用 `tauri-plugin-http`/`reqwest` 调任一 OpenAI 兼容端点，流式 token 能到 React。
   - 安装包：`tauri build` 出未签名 `.msi`，干净 Win10/11 安装并启动（检查 WebView2 是否缺失）。
4. 数据目录/日志（脱敏）/崩溃处理约定；CI（构建 + 单测）。
5. 项目骨架冒烟：启动 <3s，空聊天页可渲染。

**产出**：可运行的 Windows 桌面壳；加密 DB；五项 spike 结论表（含回退方案）；未签名安装包。
**验收**：五项全部有"可行 / 有坑 / 回退"结论；干净机器安装启动；DB 加密可验证。
**失败怎么办**：
- SQLCipher 构建失败 → `sqlcipher` 官方 amalgamation 或"SQLite + 应用层字段加密"（弱化，但可用）；
- Tauri 2 桌面阻塞 → 换 Electron（+50MB 包体，但生态稳）；core 纯 TS 不受影响；
- WebView2 缺失 → 安装包内置 Evergreen Bootstrapper，首次启动引导安装。
**参考人日**：15–20（A 线大头）。

### Step 2 · 数据管道（第 2–3 周）

**目标**：把真实聊天记录变成可统计、可检索、可解释的结构化资产。

**要做的事**：
1. **T03 适配器框架 + 5 个实现**：`wechatmsg_txt` / `wechatmsg_csv` / `liuhen_json` / `qq_txt` / `plaintext_paste`（插件注册；sniff + parse）。
2. 解析：编码探测（jschardet 试探 + 用户可手动指定）、时间戳正则族、说话人判定（显式字段 → 缩进/前缀 → 手动映射 → LLM 兜底）、系统消息分类、去重。
3. **T04**：burst（同人 <90s）、latency（截断 86400）、reply_to 补全。
4. **T05**：体检报告（总数/她的条数/跨度/夜间比/冲突段/语音比/fidelity 三档/missing/advice），前端展示。
5. **T35（建议进 MVP）**：媒体导入——图片按 `msg_id` 关联、语音条播放（先支持已解密文件）；过期/缺失给明确提示。
6. 导入体验：拖拽、进度、取消、**中断续跑**、失败样本可导出；5 万条性能实测。
7. **T39 起步**：从真实对话抽 50 个黄金情境；写盲测协议。

**产出**：归一化 JSONL、适配器注册表、体检报告、媒体库结构、导入向导、黄金集 v0。
**验收**：3 种格式各 1000 条无异常；5 万条 <90 秒；burst/latency 抽检 30 条 >90%；报告能回答"数据够不够"；中断后可续跑。
**失败怎么办**：真实数据格式太脏 → 先把"手动映射说话人 + 手动指定编码"做成可视化步骤（比重写解析器便宜）；媒体导不出 → 明确提示并可跳过，不阻塞主流程。
**参考人日**：20–26（含媒体）。

### Step 3 · 人格蒸馏（第 2–4 周，与 Step 2 并行）→ Gate G1（盲测 ≥40%）

**目标**：产出"可执行的人格资产"，而不是一篇读起来像的散文。

**要做的事**：
1. **T06 情绪标注**：20 条窗口、200 条/请求、24 标签枚举、JSON 严格校验、失败重试/跳过、**断点续跑 + 幂等**。
2. **T07 校准**：随机 200 条人工标注（W1 就要定标注人、写手册、双人复核），算 Cohen's Kappa；<0.6 必须重写 Prompt 或换模型。
3. **T08 Style Card**：句长分位、burst、标点比、emoji、2–4gram 口头禅 + PMI、typo、语音比、夜间比、延迟对数正态、开场白、称呼演变。
4. **T09 Episode 切分**：时间 + 话题；人工抽检 20 个。
5. **T10 情境-反应对**：每条必须带 `quote` + `evidence_msg_ids`，无证据丢弃；30–60 条取 top40；冲突条目保留。
6. **T11 事实抽取 + Fact Lock**：人物/地点/日期/习惯/事件/偏好；confidence<0.6 不入锁；`relationship='已分手'` 标 `suspended`。
7. **T34 人格卡审阅 + Correction 层**：人类可读摘要（report.md）可编辑，改完下一轮生效，可回滚；新增 `correction` 表。
8. **T44 渐进式人格**：T+0 秒用统计 Style Card + 3 条金句先能聊；后台继续跑标注/pairs/facts，完成后热替换，**不重复计费**。
9. **T30a 最小评测 harness**：回放 + 盲测可一键跑；holdout 冻结校验。

**产出**：prompts（label_emotion / extract_pairs / extract_facts / summarize）、style_card.json、persona_graph.json、facts.json、baseline.json、report.md、Correction 表、harness v0。
**验收**：1000 条标注成功率 >98%；Kappa ≥0.6；每 persona ≥30 条情境对且无证据=0；20 条事实人工核对 >85%；人格卡改 3 处下一轮生效；导入后 30 秒内可开聊。
**G1 门**：用 holdout 跑第一次盲测（单轮、无记忆也可），**混淆率 <40% 立即停**，回数据/蒸馏，不要做 UI。
**失败怎么办**：Kappa 不达标 → 先换模型（用 fast 角色）再改 Prompt；情境对质量差 → 强化证据链与人工抽检；盲测低 → 先加"检索原话 few-shot"（性价比最高的提分项）。
**参考人日**：35–45（含人工标注与评测）。

### Step 4 · 情绪引擎 + 记忆（第 4–6 周）

**目标**：让她有"状态"和"记忆"，而不是每轮重新扮演。

**要做的事**：
1. **T12** 四轴状态（valence/arousal/closeness/defensiveness）+ weather + tension；惯性衰减（half-life 180min）；单轮变化硬限（|Δv|≤0.35、|Δc|≤0.3）。
2. **T13** 刺激→情绪转移矩阵（3×3 × 8 类刺激）；小样本平滑/回退默认参数。
3. **T14** Arc Director：四类场次（日常/深夜/回忆/和解）+ 温度预算 + 强制转向；"3 轮内递台阶"的计数口径写死。
4. **T15** Comfort Governor：归因/上限/出口三律；脆弱度六信号（其中"单日时长"需要先做会话时长埋点，别依赖 P1）。
5. **T16** 检索：FTS5（trigram）+ BM25 + 情绪一致加权 + 时间/重要性 + LLM 重排；向量检索 P1 可关。
6. **T17** 四层记忆装配（L0 近 20 轮 / L1 摘要+open_loop / L2 top5 / L3 关系状态），token 预算 <3000，定义截断策略。
7. **T18** 未闭合话题检测与生命周期（open/resolved/expired，7 天）。
8. **T43** 事实锁运行时对抗集（改写事实/改关系/追问 AI/要求说没说过的话）+ "5 个只有你们知道的细节"题库。
9. **T45** 本地漏斗埋点表（导入/首条/主动回复/时长/负向反馈），可查看/可删除、不上传。

**产出**：情绪状态机、转移矩阵、Arc、Governor、检索与记忆装配、对抗集、本地统计页。
**验收**：单测覆盖边界与惯性；4 类场次各 10 轮回放；20 个对抗样例全部拦截；top5 相关率 >70%；注入 token <3000；open_loop 10 例中 8 例正确；DoD 5 细节命中 ≥5/8。
**失败怎么办**：中文检索不达标 → 应用层 2-gram 分词兜底；情绪误判 → 先保守阈值并记录 internal/expressed 对照；记忆错乱 → 优先事实卡与时间线，再调检索权重。
**参考人日**：30–38。

### Step 5 · 对话运行时 + 模型 + 主动消息（第 6–8 周）→ Gate G2（盲测 ≥50%）

**目标**：端到端"能聊、像活人、会主动"。

**要做的事**：
1. **T19 模型层**：`OpenAICompat`（7 家预设 + 自定义 base_url）+ 角色路由（main/fast/embedding）+ 重试/降级（401/429/5xx/拒答/超时五类分支）+ Key 存 Windows 凭据管理器 + "测一下"。
2. **T20 Compose**：Layer0 硬规则 + Style Card 硬约束 + 当前 expressed 情绪 + Arc 预算 + 3–5 组情境对 + 3–6 条记忆 + 最近 12 轮；流式输出。
3. **T21 AI 味过滤**：8 条规则 + 句长/emoji/排比/破折号/套话；单测 + 真实回复误杀率。
4. **T22 Decide**：回复概率、对数正态延迟 × busy × mood、burst、emoji/语音、已读不回。
5. **Emit**：typing + 分段 + 抖动 + 取消输入。
6. **T31 撤回**：`recallLast`、系统提示"对方撤回了一条消息"、2–6 秒后重发、负例入库；被撤回内容从上下文/记忆/摘要彻底剔除；防滥用（20 条内 3 次/日 10 次/3 秒冷却）；她也 3% 主动撤回。
7. **T38 主动消息（PC 版）**：欲望×机会 + 预算（日 3/周 12/免打扰/连续未回降频）+ reason 可读；**托盘常驻时用进程内定时器 + 即时通知**；完全退出时记录队列，下次启动补发；通知文案用她的口吻。
8. 端到端最小壳/CLI：从输入到分段出字全链路；成本/延迟实测（3 家 provider × 100 轮）。

**产出**：运行时流水线、过滤器、撤回、主动队列与托盘通知、模型设置页逻辑、端到端可运行版本。
**验收**：3 家 provider 流式正常；首 token <2s（不含拟人延迟）；误杀率 <10%；撤回后聊 5 轮仍无残留；7 天预算模拟不超限；关窗后仍能收到通知；重启补发。
**G2 门**：盲测 ≥50%；主动消息回复率（内测或模拟）≥30%；不达标就砍主动或回 Step 3/5 调检索与 Prompt。
**失败怎么办**：模型拒答 → 切备用 provider + 降级话术；API Key 配置失败 → 一键测通 + 7 家图文教程 + 成本估算器；主动像骚扰 → 收紧预算与免打扰，宁少勿多。
**参考人日**：36–44。

### Step 6 · 界面 + 引导 + 安全 + PC 打包（第 8–12 周）→ Gate G3（可安装）

**目标**：把"能聊"变成"像一个真的聊天软件"，并能在别人的电脑上装起来。

**要做的事**：
1. **T24 聊天壳**：虚拟滚动、时间分隔（>5 分钟）、左右气泡、文本/图片/语音气泡、系统提示、typing 三点（可取消 8%）、流式打字、分段到达、已读、长按菜单（复制/引用/撤回/删除）、撤回动画、下拉"那年今天"；**AI 角标常驻不可覆盖**；设计 token 对齐 02 §12.2。
2. **三扇门**：日常默认；"翻一翻"入口（回忆 3–5 轮 + 出口"回到现在？"）；23:00 后深夜变暗/降速。
3. **T26 4 步引导**：三屏说明 + 18+ 年龄校验 → 导入 → 体检报告 → 人格卡审阅 → 模型配置；**已有导出文件 → 5 分钟首聊**（配合 T44）。
4. **T27 模型设置页**：服务商选择、key 粘贴、测一下、模型下拉、成本估算器、申请教程链接。
5. **T34 人格审阅页 / T36 安全页**：人格卡编辑与回滚；危机资源、90 分钟提醒、降频/退出入口。
6. **T29 安全**：数据库加密、启动 PIN（可选）、一键销毁（含 WAL/SHM/FTS/media/logs/Keychain 残留，30 秒计时与回执，文案写"已从本机删除"而非"不可恢复"）、日志脱敏、网络白名单（仅用户配置的 endpoint）。
7. **T37 AI 标识**：每条她的消息角标 + 导出水印 + 隐式元数据；分享/截图提示。
8. **T33 备份/恢复**：本机加密导出包 + 导入恢复（换电脑）。
9. **T28-PC 打包**：`.msi`/`.exe`、图标与安装向导、签名、卸载流程（提示数据是否保留）、可选自动更新（V1.1）。
10. 拟人细节逐条录像验收；DPI/多屏/窗口尺寸测试；中文输入法测试。

**产出**：完整 PC 客户端、4 步引导、设置与安全页、签名安装包、更新通道（可选）。
**验收**：8 条拟人细节逐条通过；已有导出文件 5 分钟内首聊；设计走查；销毁取证；Win10/11 干净机安装启动；SmartScreen 无警告；升级不丢数据。
**失败怎么办**：SmartScreen/杀软误报 → 签名 + 向 Microsoft 提交审核 + 版本化发布；DPI/渲染问题 → 固定 WebView2 版本并做 100%/125%/150% 测试；进度太长 → 先出未签名内部包给 5 人试用，签名到位再发。
**参考人日**：45–55。

### Step 7 · 评测 + 内测 + 发布（第 12–16 周）→ Gate G4（发布）

**目标**：用数据证明"可以做"，然后发出去。

**要做的事**：
1. **T30b 正式评测**：300 条真实 + 300 条生成盲测（holdout）；情绪收益问卷（孤独/难过/平静 1–10）；负向放大率；出戏点清单。
2. **T46 跨模型回归**：50 条输入 × 3 模型，比对风格距离与禁用词，验证 DoD 6。
3. **T39 收尾**：黄金集扩到 50 条并接入 `pnpm eval`；每次改 Prompt 必跑 CI。
4. **内测**：10–20 人 × 2 周（知情同意、可退出、危机转介）；每天记录情绪日记与出戏点；主调 Governor 阈值与 Decide 参数。
5. **合规文档**：隐私政策、用户协议、AI 标识说明、数据删除说明（桌面端无 APP 备案/商店要求；软著可后补）。
6. **T41/T42 发布**：GitHub Releases + 官网下载页 + 版本说明 + 更新清单；崩溃/问题反馈渠道（不上传日志）。
7. **DoD 对照**：PC 版 DoD 10 条逐条打勾；输出发布报告。

**产出**：盲测报告、情绪收益报告、内测总结、合规文档、发布包与官网、更新通道。
**验收**：盲测 ≥50%；平静度 +1.5；负向放大率 <5%；PC 版 DoD 10 条全部成立；干净机器可下载安装。
**失败怎么办**：盲测不达标 → 回 Step 3/5 加检索 few-shot 与过滤，不加新功能；负向放大率超标 → 从严 Governor 与主动预算；内测招募不足 → 自己 + 朋友 5 人先跑 2 周，再扩到 20 人。
**参考人日**：30–38。

## 8. 如果只有你一个人（或全 AI 代理）

按"验证优先"压缩：
1. **第 1–2 周**只做 Step 0 + Step 1 + 一条导入链路；
2. **第 3–6 周**做 Step 2 + Step 3（用 1/3 数据先跑通），**第 6 周必须跑第一次盲测**；
3. 盲测 <40% 就停，回数据/蒸馏；≥40% 再继续 Step 4–6；
4. UI 用现成组件库 + 简化版（先单窗口聊天页，不做三扇门动画）；
5. 跳过 macOS、自动更新、开机自启；主动消息先只做"应用内 + 托盘通知"；
6. 内测找 5 个朋友跑 2 周即可，不要等 20 人；
7. AI 代理负责编码，你只做四件事：验收、真机测试、评测判定、合规与对外沟通。
> 单人 + AI 的现实周期：**6–8 个月**；但前 6 周就能知道方向对不对。

## 10. 未来补移动端要守住的 5 条纪律（本次不做，但不能堵死）

1. `packages/core` 纯 TS：不出现 `window` / `fs` / `fetch` / `localStorage`，平台能力走 `DbPort / HttpPort / ClockPort / NotifyPort / KeyPort`。
2. 数据格式带 `schema_version`，迁移脚本可重放；导出包跨端可读。
3. UI 不直接调 Rust 命令，统一走 core 的 `CoreAPI`。
4. 通知/托盘/自启等平台差异封装在 `platform/` 适配层，业务层不知道"这是 Windows 还是 Android"。
5. 主动消息的"调度"与"投递"分离：调度是纯逻辑（可测），投递是平台实现（PC=托盘+通知，移动=本地定时通知）。
