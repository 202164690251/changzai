# Step 0 · Holdout 协议（评测数据隔离）

> 没有 holdout 的盲测 = 自己考自己。本协议在 Step 0 冻结，Step 3 起强制执行。

## 1. 定义

**holdout**：从导入数据中随机抽取、**永不参与蒸馏/检索/记忆构建**的「她的真实回复 + 前后文」，只用于评测引擎生成得有多像。

## 2. 怎么抽

1. 在导入并完成基础清洗后（Step 2 结束前），用固定随机种子抽取：
   - **条数**：300–500 条她的回复（建议 400）
   - **覆盖**：按时间分层（早/中/晚三段各约 1/3），避免只抽到热恋期
   - **类型**：文字为主（≥95%），可含少量表情/语音转写；避免系统消息
2. 每条样本至少包含：
   ```json
   {
     "sample_id": "ho_0001",
     "target_msg_id": "wx_20230520_0001",
     "target_text": "。",
     "context": [{"sender": "me", "content": "在干嘛"}, {"sender": "her", "content": "刚洗完澡"}],
     "ts": 1684598400000,
     "expected_reaction_type": "冷淡/回避",
     "holdout_version": 1
   }
   ```
   `expected_reaction_type` 可先留空，由产品负责人在 Step 3 人工标注。
3. 保存为 `data/eval/holdout.v1.jsonl`，单独目录，**不放进产品 data 目录**。

## 3. 冻结纪律（硬规则）

- 蒸馏 pipeline 的输入**只允许**读取 `data/import/`，禁止读取 `data/eval/`。
- 检索/记忆写入后，用 `msg_id` 黑名单二次校验：任何 holdout 的 `target_msg_id` 不得出现在 DB 的 `message`/`memory` 表。
- 每次构建人格后运行校验脚本（Step 3 提供）：`holdout_leak_check`。
- holdout 一旦冻结，**只增不改**；换版本时新建 `holdout.v2.jsonl`，旧版本保留。

## 4. 用途

| 评测 | 用法 |
|---|---|
| 盲测 | 300 条真实回复（来自 holdout）+ 300 条生成回复混排，人/AI 判断 |
| 回放 | 给定 `context`，让引擎生成，对比语义相似度与风格距离 |
| 细节命中 | 从 holdout 中抽 10 个"只有你们知道的细节"做客观题 |
| 负向放大率 | 内测用户会话前后自评问卷（与 holdout 无关，但同一批用户） |

## 5. 隐私与伦理

- holdout 含第三方（前任）个人信息，仅用于本机评测，不上传、不分享。
- 用于内部盲测的样本需去标识（人名/手机号/地址替换）。
- 内测协议须写明：可随时退出、数据可删除、危机时提供求助资源。
- 若未来开源，holdout 数据**永不入库**（只放 schema 示例）。
