# Step 0 · 数据导出指引（Windows 微信）

> 目的：把「你和 ta 的聊天记录」变成产品可导入的文件，并确认图片/语音的可得性。
> 原则：**只处理你自己的数据；不上传、不分享、不用于训练共享模型。** 导出前先备份原始数据。

## 1. 为什么必须先在 PC 上做

- 微信 4.x 的本地数据库是加密的（SQLCipher），手机端无法直接导出；主流工具都要求在 Windows 微信上操作。
- 微信会自动清理过期图片/语音：**手机上显示"已过期"的媒体，任何工具都导不出**。所以越早导出越好。
- 文字 100% 可导；图片需要解密 `.dat`；语音是 SILK 编码，需要转码（可选）。

## 2. 推荐工具（外部工具，不内置于产品）

| 工具 | 用途 | 输出 | 备注 |
|---|---|---|---|
| WeChatMsg / 留痕 | 导出聊天记录 | txt / csv / json / html | 支持按联系人/时间段导出 |
| wechat-dump 类工具 | 解密媒体（`.dat` → 图片） | jpg/png | 版本敏感，需按教程操作 |
| ffmpeg | SILK → wav/mp3（可选） | 音频 | 语音转文字可用 Whisper（P1） |

> 版本提示：微信 4.x 的图片有 XOR / V1 / V2 三种加密（2025-08 后多为 V2，需要从运行中的微信进程取密钥）。工具链更新频繁，导出失败先确认工具版本与微信版本是否匹配。

## 3. 操作步骤（建议）

1. **备份**：把 `WeChat Files` 整个目录复制一份到移动硬盘（防止导出过程损坏）。
2. **登录 Windows 微信**：保持登录状态（部分工具需要读取运行中进程的内存密钥）。
3. **选择联系人**：只导出目标会话，减少数据量与隐私面。
4. **导出格式**：优先 **json**（字段最全），其次 txt、csv。
5. **导出媒体**：如工具支持，同时导出图片/语音到独立目录（产品会按 `msg_id` 关联）。
6. **脱敏**：导出文件里可能包含手机号、地址、身份证等；在导入产品前请自行确认，产品只在本机处理。
7. **封存 holdout**：按 `step0-holdout-protocol.md` 随机抽出 300–500 条她的真实回复，单独存放，**绝不再导入蒸馏流程**。

## 4. 产品支持的导入格式（目标）

- `wechatmsg_txt`：`2023-05-20 14:03:22 小林` + 换行消息体
- `wechatmsg_csv`：`时间,发送人,内容` 或工具默认列名
- `liuhen_json`：留痕导出的 JSON
- `qq_txt`：QQ 导出 txt（可选）
- `plaintext_paste`：直接粘贴（`时间 发送人: 内容` 每行一条）
- `chatdata_js`：网页导出 `data.js`（`window.CHAT_DATA = [...]`，自动展开语音转写）

## 5. 导出后的自检清单

- [ ] 能看到至少 2 个时间段的对话（避免只有几天记录）
- [ ] 发送人字段可区分"我"和"ta"（否则需要手动映射）
- [ ] 随机抽 10 条，时间戳与微信里显示的一致
- [ ] 图片/语音目录存在（有则记录数量；没有则产品走"无媒体"模式）
- [ ] 文件已备份到第二块磁盘
- [ ] holdout 已单独抽出并封存

## 6. 现实预期（写进产品文案）

- 普通用户从零开始导出，**中位数可能需要 20–45 分钟**（下载工具、找目录、解密、重试）。
- 因此产品指标定义为：**已有导出文件 → 5 分钟内开始聊天**；从零开始含导出单独计时，不混用。
- 如果确实导不出来，走降级路径：10 个问题的"手工描述"生成基础人格（Step 3 实现）。
